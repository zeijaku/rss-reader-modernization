# V1.52.0 SLG Widget — D0 開発契約

基準は 2026-11-24 の仕様監査書 §1〜6 と main `79bf9bf`（1.51.0）。D0 の成果物は仕様、テストデータ、データの整合性検査。Game の登録は D1、Stage 1 の実地形は D2、対 CPU 完走は D4 の受入条件とする。

## 合意済みの基準値

| 兵種（Fixture の型名） | HP | 移動力 | 射程 | ダメージ | 費用 |
|---|---:|---:|---|---:|---:|
| 歩兵 infantry | 3 | 4 | 1 | 1 | 4 |
| 偵察兵 scout | 2 | 7 | 1 | 1 | 5 |
| 射撃兵 ranged | 2 | 3 | 2–3 | 1 | 6 |
| 重装兵 heavy | 5 | 3 | 1 | 2 | 8 |

Stage 1「前線突破」は 16×12、主経路＋平地迂回。両軍とも本陣1、歩兵2・偵察兵1、初期資金8、同時保有上限6。中立資源施設1、中立工場0。ステージと難易度は独立。Easy / Normal / Hard / Nightmare で初期状態、合法手、公開情報、ユニット性能は共通。D4 は Easy / Normal を対象とする。

移動は4方向。平地・道路・施設はコスト1、森林・丘陵は2、山岳・水域は通行不可。味方は通過のみ、敵は通過も停止も不可。敵隣接による停止はない。攻撃は距離がマンハッタン射程内かつ射線が通れば命中。施設か森林にいる防御側へのダメージは1軽減、下限1。施設タイルには施設の地形効果だけを適用する。

## 状態遷移と、D0 で採用した境界条件

| 現在 | イベント | 次の状態・永続化対象 |
|---|---|---|
| 空き／既存スロット | 新規開始 | 空きなら開始。既存なら上書き確認。取消時は世代も盤面も維持。開始時は player の第1ターン。 |
| ターン開始 start | 開始処理 | 収入と処理済み印を1組で確定し acting へ。第1自軍ターンは双方とも加算0。 |
| acting・手番側の未行動ユニット | 選択 → 移動先（現在地も可）→ 攻撃／占領／待機を選択 | 移動先に部隊を表示し、その位置で可能な行動だけを提示。取消または画面を閉じると、確定盤面に戻る。 |
| 下書きあり | 最終確定 | 手番・生存・未行動・経路・コスト・行動の合法性を再検証。合法なら移動と選んだ1行動と結果を一括反映。不合法なら全項目不変。 |
| acting | 生産確定 | 施設・資金・部隊枠・指定マスを再検証。資金、生成ID、施設使用印、新ユニットの行動済み印を一括反映。 |
| acting | ターン終了 | 下書きを破棄。占領継続の失効を処理し、次陣営の start へ。CPU の確定行動にも同じ規則を適用。 |
| acting | 本陣占領2回目／投了確定 | 同じ確定処理内で finished と勝者・理由を記録。以後の攻撃・生産・収入・手番交代を拒否。 |
| 任意の確定状態 | 中断・再開 | 最後に確定した状態を復元。UIの選択やCPUの候補列は復元対象外。finished は結果表示に復帰。 |

- **本陣**　初回は所有権を維持し、占領者のIDと手番を記録。同じユニットが生きて本陣上に留まり、次の自軍ターンに占領を確定すると所有権が移る。被弾だけなら継続。確定移動で本陣を離れた時、撃破時、次の自軍ターンに別行動を確定した時、または占領せず手番を終えた時に失効。同じ本陣上の他ユニットは初回から。占領は全兵種可、攻撃との併用不可。全滅・資金0・長期戦では自動決着しない。進行不能の可能性は継続／投了を選べる警告に留める。
- **丘陵と反撃**　「静止」は直近の自軍ターンに確定移動がないこと。攻撃時は今回確定する移動も含む。丘陵の射撃兵のみ最大射程4、最小射程2は維持。相手ターン中は直前の自軍手番の履歴を参照し、次の自軍手番に切り替える。初期配置・生産は移動に数えない。反撃は生存・射程・射線条件を満たす側が1戦闘に1回。通常行動を消費せず、別の攻撃には再度反撃できる。反撃への反撃は発生しない。
- **射線**　始点・終点のマス中心を結ぶ線分と山岳タイルが辺または角で接触したら遮断（Supercover）。両端を交換しても結果は同じ。施設・ユニット・森林・丘陵・水域は透過する。
- **経済**　第2自軍ターン以降の開始時に所有本陣+3、所有資源1つにつき+2。施設の所有権変更は即時で、収入・生産は取得側の次の手番から。施設を保有するだけで移動地形やユニット能力は変化しない。占領費・維持費0。資金のゲーム上の上限なし。
- **生産**　本陣は歩兵、工場は全兵種。隣接4方向のうち、盤内・通行可能・空いているマスを生産者が指定。CPUも同条件。施設ごとに自軍1ターン1体。部隊数が上限と同数なら不可、所持金が費用ちょうどなら可。生成時に当該手番の行動済み印を設定し、次の自軍ターンから行動可能。

## 保存スキーマ v1（D6 が実装する契約）

[型と必須項目](../tests/fixtures/slg/checkpoint-v1.schema.json) ／ [Stage 3・CPUの3件目確定直後の有効例](../tests/fixtures/slg/checkpoint-v1.json)。施設の位置・種類と地形は stageId と stageRevision が示す不変定義から取得する。例の revision はテスト専用。

| 項目 | 意味・検証 |
|---|---|
| schema, generation, ownerId | 既知のスキーマかつログイン中の正のユーザーIDと一致。世代はスロットごとに成功書込みで単調増加し、新規ゲーム上書きでも継続。 |
| stageId, stageRevision, difficulty, seed, rngState | 対応する盤面定義と難易度を確認。初期seedと確定済み行動直後の乱数状態を保存。 |
| ply, phase, incomeAppliedPly | ply は1起点の陣営手番。奇数 player・偶数 cpu、各陣営の第1手番は1・2。start では収入印が ply−1、acting／finished では ply。0は未処理。開始処理は資金と印を同時更新。 |
| units, nextUnitId | 生存ユニットのみ。固有ID・座標・陣営・型・HPを保存。ID再利用なし。0始まりの盤内座標、通行可、重複なし、兵種別HP・各陣営の部隊上限を検証。 |
| actedPly, movedPly（unit） | 0か当該ユニットの過去・現在の自軍手番。移動印≦行動印。同手番の行動済みは再行動不可。履歴を敵手番開始時に消去しない。 |
| facilities | ステージ定義の全施設IDを重複なく保存。owner は player／cpu／中立。acquiredPly は初期0または取得手番。producedPly は未使用0または最後の生産手番。資源施設の生産印は0。 |
| capture（facility） | 通常は null。本陣の1回目だけ unitId と firstPly。参照先は本陣上の生存敵ユニット。継続可否はID・直後の自軍手番・未行動を照合。2回目確定時に消去。 |
| funds, cpuActionsDone, result | 両軍資金は非負整数。CPU手番の確定コマンド数（移動＋行動は1件、生産も1件）と盤面・乱数を同時記録。手番交代で0。CPUは現在の合法手から残りを再計算。結果は finished のみ winner＋reason（hq／resign）。 |

- 同一origin・ブラウザ内で `rssReader.slg.user.<ownerId>.save` に全Stage共通1スロット。直前の正常な世代は同接頭辞の `.previous`、クリア実績は独立した `.clears`。Game Widget のID、既存GameのBestキーとは独立。種類変更・削除でも維持する。
- 同一ページの複数Widgetは1つの状態を購読。別タブでは保存直前の世代照合と storage イベントで競合を検出し、旧世代の操作を止めて読み直しを促す。localStorage の照合と書込みには競合の余地がある。
- 読込はサイズ、JSON、schema、所有者、ステージ整合性の順で検証。破損・未知版・未知stageRevisionは元データを保全し、正常な前世代の復元を明示選択。容量超過・アクセス拒否は画面内のみの継続を表示。保存サイズの数値上限はD6で最大ステージの実データを計測して固定する。

## 回帰に引き継ぐ Fixture

[盤面・操作・期待値](../tests/fixtures/slg/rule-cases.js) ／ [D0 整合性検査](../tests/test_current_slg_d0.js)。実行は `node tests/test_current_slg_d0.js`。D2〜D4は同じ期待値を製品の公開関数で再生して検証する。

部分盤面は左上 (0,0)。記号 . 平地、r 道路、f 森林、h 丘陵、m 山岳、w 水域。施設は指定座標の基本地形を「施設」にする。省略時は player の第1手番の開始処理済み、両軍資金8、HP満タン、全ユニット未行動、上限6、次のユニットIDは既存最大+1（空なら1）。部分盤面に省いた施設からは収入を数えない。これらはStageの配置データと独立。

| ID | 固定した期待値 |
|---|---|
| MOVE-01〜05 | 最小移動費用・超過・味方通過・敵封鎖・盤外・仮移動取消。 |
| ATK-01〜06 | 先制撃破、反撃順、軽減下限、最短射程、遮蔽物と角接触、丘陵の移動履歴。 |
| CAP-01〜04 | 全兵種の通常占領、再行動拒否、両陣営の本陣決着、撃破・離脱・手番スキップによる失効。 |
| ECO-01〜04、TURN-01〜02 | 双方の収入時点、生産拒否時の資金維持、施設・兵の再使用、全滅・資金0での継続と投了。 |

costs の null は停止不可。hits は攻撃順の [攻撃者, 対象, 実ダメージ]。funds の順は [player, cpu]。capture の [unitId, firstPly] は50%。acted は該当手番の行動済みID、at／hp／owner は指定した項目だけを比較。rejected または checkpoint=unchanged は、盤面・印・資金・乱数・世代を含め確定状態全体が同一であること。D0検査は移動費用と射線を独立計算し、期待する命中列・資金の整合と保存サンプルを検査する。実ゲームの操作成功率やCPUの強さは後続工程で測る。

| 保存・復帰ID | 入力 → 期待値（D6で動作テスト） |

| SAVE-01／02／03 | Stage 3例を再読込 → 同じHP・資金・占領者。CPUは3件確定済み、行動可能な既存兵はID 7だけ、手番8の収入再加算0。 |
