# ICS購読 Dev1：登録・取得基盤（v1.51.0-dev.1）

## 実装内容
- 既存v1.49.1のmainを基点とした独立した開発ブランチ。Precision Sniperは含めない。
- Calendar管理モーダルに「外部Calendar（ICS購読）」を追加。名前・識別色・HTTPS URLを登録し、変更・削除・手動取得できる。
- 保存URL（パスとQueryに秘密トークンを含む）は一覧APIに返さず、ドメインのみ表示。URL変更時は空欄に新URLを入力し、旧キャッシュを破棄する。
- 新テーブル `calendar_ics_subscription` でユーザーごとにURL・取得結果・未解析本文を保持（最大10件／ユーザー）。
- 既存の認証・CSRFチェックがある `calendar_source_api.php` に `calendar.ics.*` アクションを追加。公開PHPファイルを増やさない。
- HTTPSのみ、標準443番ポート、URL認証情報なし。既存SSRF対策済み `app_safe_http_fetch` を使用し、DNS検証・公開IP固定・各リダイレクト再検証・TLS検証・タイムアウト・容量上限を維持。HTTPSからHTTPへ転送されたら拒否。
- 最大1MiBのICSを取得。外枠の `BEGIN:VCALENDAR` / `END:VCALENDAR` だけを検証し、元データは非公開キャッシュに保持。1分以内の連続取得を制限。
- 取得エラーはコードのみ保存し、URLや外部応答本文はログ／画面へ返さない。失敗時も最後に成功したICS本文を保持。

## 対象外（Dev2 / Dev3）
- Dev2：VEVENT解析、RRULE/EXDATE/RECURRENCE-ID、TZID変換、既存Calendarの日／週／月表示とフィルター連携、外部予定の編集不可制御。
- Dev3：アクセス時／cronの定期更新、HTTPキャッシュ条件付取得、更新頻度設定、本番向け検証と正式化。
- RSS Reader自身のICS URL発行（ICS公開）はさらに後の機能。

## DB Migration（必須）
既存MySQL/MariaDB環境は **`database/migrations/035_v1_51_calendar_ics_subscription.sql`** を、アプリ更新前に適用。
`@table_prefix` を既存 `DB_TABLE_PREFIX` に合わせること。既存の001〜034を再実行しない。035は新テーブルの `CREATE TABLE IF NOT EXISTS` のみで、既存予定を移行しない。
新規インストールでは更新済みの `database/schema.sql` を使う。
マイグレーションを実行せずDev1 UIを利用すると、ICS操作だけ503になります（通常Calendarは維持）。

## Dev1更新方法
既存v1.49.1のアプリルートにDev1更新用ZIPを展開（`app/`, `public/`, `database/` が直下になる場所）。
まず本番相当のコピー環境でDBとコード一式をバックアップしてから適用すること。プライベート設定、`var/`、DBデータ、ユーザーファイルを削除しない。
フッターで`1.51.0-dev.1`を確認し、Calendar管理からICS登録・取得・変更・削除を確認する。
開発用のDev16 Precision Sniper環境には上書きしないこと（main基点の独立機能）。
取得したICSの予定がまだカレンダー画面に表示されないのはDev1の仕様。

## テスト・注意
`php tests/test_current_calendar_ics_dev1.php`、既存PHP 8.1／8.4回帰・Apache検査・GitHub CIを実施。実サイトとの通信は利用者環境での確認が必要。
秘密URLはDBに平文で保存するため、DBバックアップ・PHP/Apacheアクセスログ・管理者権限を厳格に扱うこと。UIや通常APIへURLを出さない設計とする。
ロールバックでは追加したPHP/JS/CSSコードをv1.49.1へ戻し、035で作成したテーブルはユーザーの明示判断なく削除しない。
