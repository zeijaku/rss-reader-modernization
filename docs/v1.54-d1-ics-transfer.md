# V1.54 D1 — ICS transfer foundation

- Apply migration 037 after 036 on existing databases (maintenance window; back up first). Fresh installs use schema.sql. The existing migration marker convention requires checking column/index manually if DDL succeeds but marker writing is interrupted. Backfill is repeatable; verify no NULL UIDs remain before enabling export.
- New events receive opaque UUIDv4 in their existing transaction, with compatibility for pre-037 schemas. SQL backfill uses hashed UUIDs, never exposes host identifiers. Export never changes data. UID comparisons are byte-sensitive; nonunique index avoids breaking existing source move/delete semantics. D3 must handle duplicate imported UIDs and source moves explicitly.
- Authenticated CSRF POST api_v1.php action calendar.transfer.export, source_id; returns JSON with filename and ics. D1 only: selected local calendar, basic non-recurring events; no UI until later checkpoint. D1 deliberately rejects a calendar containing a recurrence or unrepresentable multi-day open-ended timed event. No full migration/backup claim. D2 adds recurrence, metadata, reminders, period and ZIP.
- Time semantics: JST -> UTC, inclusive internal all-day end -> exclusive ICS DTEND; UTF-8 folding at 75 octets. No outbound access or external subscription export.
- No version/release bump until formalization. Memo untouched.
