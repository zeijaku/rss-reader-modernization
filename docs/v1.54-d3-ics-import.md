# V1.54 D3 — ICS import backend

POST api_v1.php (authenticated CSRF; multipart FormData text field ics, <=8 MiB): calendar.transfer.preview or calendar.transfer.import. target=existing (source_id) or new (optional name,color, otherwise ICS metadata), mode=add (default) or update, include_extra=1 default. Import submits the same raw ICS and options plus preview_token. Preview is read-only. Token HMAC binds file, owner, options, active owner state; apply locks owner/rows on MySQL, rebuilds plan and rejects stale state. Conflicts/limits block whole batch; unsupported UID groups are reported and not imported. Explicitly approved valid groups may proceed. No replacement/deletion, absent exceptions retained, no other owners. SQL transaction includes marks and reminder reconciliation. Runtime DB failure rolls back. Local timestamps represent import; no remote timestamp overwrites.

Strict bounded component parser; separate from unchanged subscription parser. Single VCALENDAR v2.0, 2000 VEVENTs, 200k physical lines, 32 KiB unfolded line, 8 MiB raw. Only equivalent daily/weekly/monthly/yearly, interval 1; COUNT bounded to 2100 converted to last occurrence; no RDATE, complex BY*, DST series, range overrides, multiple/unsupported alarms. Unsupported standard colors outside palette rejected. UID exact byte/case match per target calendar; conflicting duplicate stored UIDs block; add skips; update compares normalized values and retains absent local-only color/reminder/deadline metadata. Existing calendar name/color unchanged. New calendar explicit creation. X-RSSREADER-DAY-MARK escaped JSON restored by date. Existing marks skipped in add and explicitly updated in update. UID groups with unsupported content reported. No ZIP import or UI yet. PHP post_max_size must exceed request size for full 8 MiB. No Memo changes or new migration. D4 includes HTTP/browser and external interoperability validation.
