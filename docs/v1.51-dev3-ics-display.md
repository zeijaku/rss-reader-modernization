# ICS購読：第2工程（v1.51.0-dev.3）

## 目的
Dev1/Dev2 UI補修済みの v1.51.0-dev.2 を基点に、ICSキャッシュを解析してCalendarに表示。既存の予定DB・保存APIはそのまま。追加Migrationなし。

## 実装
Calendar月・週・日表示にICSを読み取り専用で統合。「すべて」のフィルターにICS購読単位の表示切替。通常Calendarの予定編集・登録先はローカルだけ。ICS予定はリンクアイコン・マット色を用いて区別し、クリックで詳細（タイトル・日時・場所・説明・HTTPSリンク）を表示。ドラッグ・編集・削除は不可。カレンダーの画面表示時は取得先へアクセスせず、保存済みics_rawだけを解析します。

解析項目：UID/SUMMARY/DESCRIPTION/LOCATION/URL、DTSTART/DTEND、DATE終日のexclusive終了日、DURATION、UTC/IANA TZID/主要Windowsタイムゾーン、floating日時。RRULEの日次・週次・月次・年次、INTERVAL/COUNT/UNTIL/BYDAY/BYMONTH/BYMONTHDAY/BYSETPOS/WKST、EXDATE/RDATE、RECURRENCE-IDによる変更・取消。

## 制約
iCalendar標準の全機能には対応しません。BYWEEKNO/BYYEARDAY/BYHOURなど複雑なRRULE、カスタムVTIMEZONE、RECURRENCE-IDのTHISANDFUTUREは対象外。未対応規則で存在しない繰り返し予定を作らないよう制限。ICS上限1MiB、600 VEVENT、表示中最大1200件。自動更新・双方向編集・ICS URL公開は後工程。

## 更新
v1.51.0-dev.2 のコード・DBをバックアップ後、今回の更新ZIPをアプリルートで上書き。追加SQLは不要。既存のICS購読URLと取得済みキャッシュは維持。v1.49.1や古いDev1へこの差分だけを適用しないでください。

## 確認手順
1. ICS管理で既存のGoogle購読が取得済みであることを確認。未取得なら手動取得。
2. Calendarを更新して月・週・日画面に外部予定を表示すること。予定がない期間は空で正常。
3. 「すべて」からICSの表示を切替。通常予定・Taskへの影響がないこと。
4. ICS予定をクリックして読み取り専用詳細が開くこと。編集、削除、ドラッグ不可を確認。
5. Googleの予定を変更した場合は手動再取得し、Calendarも更新して確認。第3工程まで自動再取得はありません。
6. PC・スマートフォンとテーマを確認。既存Calendar CRUDと繰り返し・通知の回帰テスト。

テストはPHP 8.1/8.4の回帰、Apache隔離、ICS parser fixtures、UI契約、ZIP CRC・SHA256。問題があればv1.51.0-dev.2の元ファイルを復元してください。DB巻き戻し不要。
