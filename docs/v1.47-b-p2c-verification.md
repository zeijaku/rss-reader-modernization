# V1.47-B P2-C：PHP公開URL境界とCSPの実動作確認

> 基準：P2-B確認版（PR #152）を継承。P0 #146／P1 #151／P2-B #152／P2-Cは未統合。
> P2-Cの本番用変更は **public/.htaccess と app/version.php のみ**。DB・Session・CSRF・CSS・JS・他のApache設定には変更なし。

## 対策目的と差分

P2-Bで、テスト環境の `AcceptPathInfo On` 条件下では、未知の `unknown.php/extra` と `unknown.phtml` がHTTP 200になることを確認した。テストではPHP実行を行っておらず、本番の脆弱性を実証したものではない。

P2-Cでは、従来の23件の許可PHPホワイトリストは変更せず、`public/.htaccess` に次のガードを追加：

```apache
AcceptPathInfo Off
RewriteRule \.(?:php[0-9]*|phtml?|pht|phar)(?:/|\.) - [F,L,NC]
RewriteRule \.(?:php[0-9]+|phtml?|pht|phar)$ - [F,L,NC]
```

- `AcceptPathInfo Off`: `index.php/extra` などのPATH_INFO付きURLを拒否する。現在のWebページ・APIはこの機能に依存していない。
- 最初のRewriteRuleは `unknown.php/extra`、`foo.php.txt`、`foo.phtml/extra` 等の複合・スラッシュ付き拡張子を拒否。
- 次のRewriteRuleは `.phtml`、`.pht`、`.phar`、`.php5` 等の別拡張子を拒否。
- **許可済みの、拡張子がちょうど `.php` で終わる23件は既存ルールをそのまま適用**。
- 全拡張子・全サーバーPHPハンドラーをカバーするとの主張はしない。運用サーバー固有のPHPハンドラー拡張子・Apache設定は別途確認が必要。
- 検証版識別子 `1.47.0-dev.3`。CSS/JSのキャッシュキーも合わせて更新するが実ファイルの内容は変えない。

## テスト設計

### Apache 2.4（両DocumentRoot方式）

`tests/test_current_p2b_apache_probe.py` を拡張し、P2-Bの既存ヘッダー契約を維持する。

- アプリルート公開、public/直接公開の両方式をそれぞれ独立した一時ディレクトリに構築
- HTTP 200：`/`、許可済み `index.php` と `api_v1.php`、`/stock`、`/settings`、`/rss-management`、`/file-library`、`/remote-files`、`/remote-editor`
- HTTP 403：未知PHP／ネストPHP／非公開領域と秘密ファイル（例外：非公開の非PHPパスは404でも拒否）
- HTTP 403または404：`/unknown.php/extra`、`/index.php/extra`、`/api_v1.php/extra`、`.phtml`、`.php5`、`.phar`、`.pht`、`.php.txt`、`index.php.txt`、サブディレクトリ
- 厳しめの試験としてApacheの親側に `AcceptPathInfo On` を設定。実際のpublic/.htaccessが安全に拒否できることを確認。
- 既存の強制CSP、Report-Only（隔離テストのみ）、各種セキュリティヘッダーを検証。

### Apache + 実際のPHPレスポンス

`tests/test_current_p2c_apache_php_csp.py`：
- 一時Apacheとlocalhost限定PHPビルトインサーバーを起動し、**一時コピーの**`.htaccess`にのみテスト用リバースプロキシルールを追加
- HTMLは共通の強制CSPのみで表示
- ファイル配信相当のPHPレスポンスに、`default-src 'none'; sandbox`、`Cross-Origin-Resource-Policy: same-origin`、`Cache-Control: no-store`を付けて返す
- 共通CSPとPHP個別CSPが**別ヘッダーとして両方保持される**ことを検証
- `unknown.php`等の禁止URLがPHPバックエンドへ到達せず403/404になることを確認
- **限定事項**：PHPバックエンドのプロキシ方式はmod_phpや実際の本番PHP-FPMハンドラーと同一ではない。本番設定を使った総合テストを意味しない。

### 既存回帰

PHP 8.1／8.4の既存CI、公開23 Endpoint契約、認証、CSRF、Cookie、ゲーム、Calendar、Remote Files等の回帰を維持する。P1のテストがdev.2を固定参照していた箇所を現行追従に変更。

## CSP方針

**P2-Cでは `script-src` / `style-src` / `connect-src` / `media-src` / `frame-src` を本番向け強制ポリシーに追加しない**。P2-BのReport-Only検証はCI隔離Apache内に限定する。

Cameraの外部動画・YouTube・HLS、DashboardやGameの動的CSS、PDFプレビューを壊さないことを優先。
厳格CSPの導入には、各機能の実ブラウザでの違反測定が必要であり、P2-CのURL境界修正と分離する。
