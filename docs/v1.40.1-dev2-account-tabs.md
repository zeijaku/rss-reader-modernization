# V1.40.1-dev2: Account Settings tabs

Application / Asset Revision: `1.40.1-dev.2`. Stable main remains `1.40.0`.

## Scope

Dashboard and settings-page Account Settings now have 基本設定 (default), セキュリティ and 認証ログ tabs. Email/password controls keep their IDs, form fields, validation and existing request handlers. Security controls remain within the original `data-account-totp-status` scope. The existing audit renderer is extracted without changing escaping or data access; its original combined-render default is retained. Stock keeps its existing email/password-only modal.

Only the selected panel scrolls; tabs and footer stay accessible. Bootstrap provides tab keyboard navigation. Reopening returns to Basic and existing modal-close handlers clear passwords / provisioning / recovery plaintext. Switching tabs retains pending inputs while the modal remains open.

No DB, API, authentication-rule, timeout, migration, external dependency or game-engine changes. Display settings / Dashboard tab settings / RSS Highlight and Widget headers remain dev3/dev4.

## Install

The incremental ZIP is for an installation already running dev1. Back up the six matching runtime files and overwrite using the archive's `app/` / `public/` paths. Reload and confirm `1.40.1-dev.2`. If starting from stable V1.40.0, use the cumulative ZIP instead. No migration or configuration changes.

## Production checks (PC and smartphone)

1. Open Account Settings from Dashboard: Basic selected; email/password headings and controls are accessible without passing 2FA/log content.
2. Switch Basic → Security → Authentication log: exactly one panel visible, active tab clear, no clipped labels or horizontal scroll.
3. On Security check the existing 2FA status, Recovery Code balance, Step-up and current/other sessions. Scroll long content: tabs and Close remain visible.
4. On Authentication log check existing rows / empty state / timestamps; no duplicate log below Security.
5. Enter test values without submitting, switch tabs and return: values retained. Close/reopen: Basic selected and passwords cleared.
6. On the settings page repeat 1–5; Stock retains its existing email/password-only modal.
7. Use Tab / arrow keys / Home / End / Enter and Escape. At 320px, landscape, text enlargement and existing dark themes check tabs / forms / close controls.
8. Test wrong-current-password and mismatched-new-password feedback on a test account. If testing successful email/password changes, use a test account and verify re-login with the new credentials.
9. If a dedicated test account is available, verify 2FA enrollment / Step-up / other-session logout and existing close-time secret clearing. Do not reset a production 2FA setup just for this UI check.
10. Check Drawer reopen, other modals and existing Widget edit / move / games still work.
