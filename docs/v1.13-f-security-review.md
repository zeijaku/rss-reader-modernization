# V1.13-F Security Hardening / Documentation review

## Scope

V1.13-B〜Dで追加・分離したEntry Pointと既存Security boundaryを再点検した記録です。V1.13-Fでは新しいDB table / column / indexは追加していません。

## Result

| 項目 | 結果 | 補足 |
|---|---|---|
| Stock / Settings認証境界 | OK | Session userを基準。未認証でprivate dataを取得しない |
| CSRF | OK | MutationはAPI dispatcher境界で検証 |
| XSS | OK | 既存escape / normalizationを維持 |
| PDO / SQL | OK | Prepared statement / owner scopeを維持 |
| SSRF | OK | Feed fetchのsafe transportを再利用。新fetch pathなし |
| Session | OK | strict / cookie-only / HttpOnly / SameSite / timeout / rotation |
| Remember Token | OK | selector + validator hash、rotation/revoke boundaryを維持 |
| CSP | 維持 | 現行限定Policyを維持。Legacy inline依存があるため拙速なstrict化をしない |
| HTTPS / HSTS | 本番確認 | HSTSは本番HTTPS強制を確認せずRepositoryへ追加しない |
| Runtime Config | 改善 | Healthcheckで秘密値なしのSecurity状態を確認可能にした |
| Private directory | OK | app/config/var等はpublic外。Runtime pathもHealthcheckで確認 |
| Secret exclusion | OK | .gitignore / repository scanを維持 |
| DB構築Documentation | 改善 | schema.sqlが008までのBaseで、fresh installは009〜012も必要と明記 |

## DBについて

`database/schema.sql` のDDLは変更していません。先頭Commentだけを現状に合わせています。

現行の新規Installは次の順です。

```text
database/schema.sql
  ↓
009_v1_9_mail_account.sql
010_v1_10_links.sql
011_v1_11_stock_tags.sql
012_v1_12_feed_keywords.sql
```

詳細は `docs/installation.md` を参照してください。

## CSP / HSTSの判断

V1.13-FではSecurity headerの数を増やすことを目的にしません。CSPは既存inline dependencyを壊さない範囲を維持し、HSTSは実際のHTTPS強制状態を確認してから導入する方針です。
