# V1.55 D1 — Memo foundation

Based on v1.54.0. Migration 038 adds only memo_format (ASCII, binary collation, text default), existing rows/body/timestamps untouched. Existing TEXT permits 16000 Unicode code points, <=64000 UTF-8 bytes. Normalize CRLF/CR to LF, retain whitespace, reject blank/invalid/control text. No format conversion; new Memo defaults to text. Markdown currently displays as escaped raw text pending D2. Existing title 32, layout and owner/CSRF unchanged.

Existing APIs accept optional memo_format (text/markdown); widget.list returns format, revision, body_sha256, updated_at. Revision covers Memo ID, Widget ID, title, exact body, format, width, height and style (not ordering/location). Update/body update accept expected_revision; new UI sends it. Legacy text-only API without format retains existing body-hash protocol (legacy settings without a hash remain accepted for compatibility; this path cannot edit Markdown/change format). New client must reload stale revision and retain draft. Format change requires revision. Body update returns new format/revision/time. MySQL row locks and transaction remain. No new endpoint. Existing controls accept up to 32000 UTF-16 units but client/server validate 16000 code points; large Memo writes use multipart, keeping existing request limits. Raw body is escaped in a separate data attribute for subsequent rendering; no HTML interpretation. No version bump, package or production change. D2 rendering/checklist, D3 editing UI, D4 management remain pending.

Migration requires visible own table metadata in INFORMATION_SCHEMA; confirm prefix before applying once, and do not run schema.sql on existing DB. Reapplication skips existing column. Fresh install schema includes column.
