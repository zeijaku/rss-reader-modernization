# V1.55 D1 — Memo foundation

Based on v1.54.0. Migration 038 adds only memo_format (ASCII, binary collation, text default), existing rows/body/timestamps untouched. Existing TEXT permits 16000 Unicode code points, <=64000 UTF-8 bytes. Normalize CRLF/CR to LF, retain whitespace, reject blank/invalid/control text. No format conversion; new Memo defaults to text. Markdown currently displays as escaped raw text pending D2. Existing title 32, layout and owner/CSRF unchanged.

Existing APIs accept optional memo_format (text/markdown); widget.list returns format, revision, body_sha256, updated_at. Revision covers Memo ID, Widget ID, title, exact body, format, width, height and style (not ordering/location). Update/body update accept expected_revision; new UI sends it. Legacy text-only body.update without format retains the body-hash protocol; it cannot edit Markdown/change format. Full settings update requires expected_revision, so old open settings forms return 409 and must be reloaded; this prevents title/layout-only lost updates. New client must reload stale revision and retain draft. Format change requires revision. Body update returns new format/revision/time. MySQL row locks and transaction remain. No new endpoint. Existing controls accept up to 32000 UTF-16 units but client/server validate 16000 code points; large Memo writes use multipart, keeping existing request limits. Raw body is escaped in a separate data attribute for subsequent rendering; no HTML interpretation. No version bump, package or production change. D2 rendering/checklist, D3 editing UI, D4 management remain pending.

Migration requires visible own table metadata in INFORMATION_SCHEMA; confirm prefix before applying once, and do not run schema.sql on existing DB. Reapplication skips existing column. Fresh install schema includes column.

Manual refresh synchronizes layout and format with the revision so an old layout cannot be re-saved under a new revision. MariaDB smoke uses the existing isolated local server pattern and a schema-scoped non-root user for Migration 038, repeated apply and 64,000-byte TEXT storage.
