# V1.54 D2 — Calendar transfer export

API: authenticated CSRF POST api_v1.php, action=calendar.transfer.export. scope=single (default, source_id required) or all (no source_id), range=all (default) or period (start_date/end_date, inclusive, max 366 days), include_extra=1 (default) or 0. Response: filename and ics string or zip_base64. UI follows in D4. No new migration.

- Full export: RRULE daily/weekly/monthly/yearly, inclusive UNTIL (DATE or UTC timestamp), EXDATE, RECURRENCE-ID using original start; timed series use Asia/Tokyo VTIMEZONE and retain seconds. Override inherits parent reminder. Restored/deleted rows excluded. Period export: effective overlapping occurrences including moved-in overrides; cancelled/moved-out excluded. Occurrence UID rr-occ-SHA256(parent UID + NUL + original date), independent of range; standalone, not a full restore of the series. Full overlapping events retain their original boundaries, not clipped.
- VALARM DISPLAY: timed relative to DTSTART; DATE relative to local midnight with 09:00 adjustment. Receiving apps may interpret DATE alarms in their local timezone. X-RSSREADER-REMINDER stores exact internal setting. Standard COLOR and NAME always included; additional metadata optional. X-RSSREADER-CALENDAR-NAME/COLOR, X-RSSREADER-COLOR/DEADLINE/REMINDER, X-RSSREADER-END-TIME (NONE or HH:MM:SS), X-RSSREADER-TRANSFER-VERSION:1. For multi-day timed events without end clock, DTEND uses final date 23:59:59; the custom end-time field preserves the original unset clock. For equal start/end clock DTEND omitted; custom field preserves exact clock. X-RSSREADER-DAY-MARK is repeated VCALENDAR TEXT (escaped JSON object with date,label,note). Day marks owner-level, once in default-first ZIP entry; single includes all matching marks. D3 must decode TEXT escapes once (not sequential replacements) and honor these attributes. No external images, subscriptions, tasks or notification state exported.
- Export limits: 2000 VEVENTs and 8 MiB per ICS, total content 16 MiB; exceed -> explicit error, not truncation. ZIP32 stored, safe numeric filenames, no temporary files/ZipArchive dependency; names are in ICS metadata. ZIP import out of scope. Read-only owner-scoped transaction, no lazy UID writes. D1 baseline serializer retained for focused tests; API uses extended serializer. No Memo or subscription parser changes. No production deployment or release bump.
