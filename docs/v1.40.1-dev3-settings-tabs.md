# V1.40.1-dev3: Settings page tabs

Application / Asset Revision: `1.40.1-dev.3`. Stable main remains `1.40.0`.

## Scope

The Settings page has four categories: 表示設定 (default), タブ設定, ユーザーリンク, RSS Highlight. All existing configuration fields, IDs, validation, PHP escaping and API request handlers are retained. Display and User links still belong to the original single `settingsForm`, saving both categories together as before. Both save buttons explicitly say 表示・リンク設定を保存. Dashboard tab names and RSS Highlight retain their independent forms and save actions.

The Settings-only local JS controller uses the already bundled Bootstrap Tab. Existing `/settings#display`, `#tabs`, `#highlight` and new `#links` open the corresponding category. Tab switches update browser history; reload / Back / Forward retain the selected category. Hash lookup uses getElementById and the Settings content scope, without raw selector or HTML interpolation. Invalid / unknown hashes fall back to Display. The script is loaded only on Settings, using app_asset_url.

The shared Drawer organizer consolidates only the three application settings links into one 設定 entry, retaining separate RSS管理 and all configured user links (even those pointing to old Settings anchors). Source PHP legacy navigation anchors remain available as fallback and do not change route compatibility. Dashboard, Stock, Settings, File Library, Remote Files and RSS management use the same organizer. Offcanvas/modal ownership and logout POST / CSRF remain unchanged.

The Settings categories use four columns on desktop, two on narrow screens, wrapping labels and at least 44px touch targets. dev1 Drawer and dev2 Account tabs remain intact. Widget headers remain scheduled for dev4.

No DB / migration / API / authentication-rule / Widget-engine / runtime dependency changes.

## Install

For an installation on dev2, back up and overwrite the five matching runtime files in the incremental ZIP using their app/ and public/ paths. Application and Asset should read `1.40.1-dev.3`. No configuration or migration changes. The cumulative ZIP is for stable V1.40.0 installations and includes dev1/dev2. Rollback restores the four previously existing changed files to dev2; remove the newly added `public/js/settings-tabs.js` after restoring public/settings.php (it is no longer referenced).

## Production checks (PC and smartphone)

1. Reload and confirm `1.40.1-dev.3`.
2. Open the Drawer on Dashboard / Stock / Settings / File Library / Remote Files / RSS management: one 設定 entry plus separate RSS管理. Existing Widget/Game categories, files and user links remain available.
3. Open Settings normally: Display selected; switch all four categories, checking all previous controls remain available and only one category is visible.
4. Open `/settings#display`, `/settings#tabs`, `/settings#highlight`, `/settings#links` directly. Switch tabs, reload and use Back / Forward: the correct category opens.
5. Change a User Links value without saving, visit Display and return: input remains. Display/User Links save together, as indicated by the buttons.
6. Save a theme / Navbar style and a User Links URL / label / icon. Reload and visit Dashboard: values and menu links are retained. Restore your preferred settings afterward.
7. Change a Dashboard tab name, save and check the Dashboard. Restore it if this was a test.
8. Add and remove a test RSS Highlight keyword; check count, feedback and highlighting. Existing keywords must remain.
9. Check keyboard Tab / arrows / Home / End; phone portrait/landscape and text enlargement. No clipped tab label or horizontal overflow.
10. Open/close Account Settings: dev2's Basic/Security/Authentication log tabs remain normal. Check Drawer reopen, other modals and existing Widget edit / move / games.

## Validation

Current regression and existing PHP render/security/route contracts cover existing boundaries. Focused browser tests render the full production Settings page with the existing isolated PDO fixture, local production JS/CSS and fixture-only API responses. They cover saved values / form ownership / duplicate-submit guard / CSRF / errors / successful fixture save and reload, legacy hashes / history, keywords, unavailable-keyword fallback, PC/mobile/themes/zoom/keyboard. Dedicated Drawer, Account and Game browser regressions cover adjacent UI.

Browser fixtures do not prove live DB writes or physical iOS/Safari/soft-keyboard behavior. GitHub PHP 8.1 / 8.4 CI and user production checks remain required before finalizing V1.40.1.
