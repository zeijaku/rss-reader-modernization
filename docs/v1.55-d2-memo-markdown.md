# V1.55 D2 — Memo Markdown display

D1 format and revision are reused. Text is default, rendered unchanged as text. Memo create/settings now select Text or Markdown; actual edit always reads the raw source, not rendered text. No new endpoint, dependency, DB column or migration. Existing Memo body API handles checklist changes, with full revision. Checklist click persists exactly one marker in source after server confirmation. In-flight controls are blocked; failure/409 leaves previous confirmed state visible and requests manual refresh, no automatic retry. Manual refresh and card replacement re-render Markdown, keep raw and format in sync. Preview rendering (D3) can reuse render(container,source,{interactive:false}).

Supported bounded subset: ATX headings 1–6, basic strong/emphasis/strike, unordered and ordered lists (flat), task list markers, inline code, fenced backtick/tilde and four-space code, bare and Markdown HTTP(S) links, angle-bracket HTTP(S) links, pipe tables with matching column counts and optional alignment/escaped pipes. Unsupported syntax remains text where practical; not a full CommonMark/GFM implementation (nested lists, arbitrary nesting, reference links, images, HTML, plugins are not supported). No innerHTML, resource-fetching nodes, style attributes, event attributes or external parser dependencies. Only HTTP(S) URLs without credentials, new tab with noopener noreferrer. Raw HTML is rendered literally; image syntax does not load images. Inline depth/lookahead/source bounded. Tables and code scroll within card, touch task labels enlarged.

Focused tests cover source offsets with emoji, same label tasks, URL safety, actual PHP markup with Chromium at 1280 and 360px, successful and stale checklist update with mock browser API plus real SQLite API/transaction tests. Existing MariaDB/Calendar tests continue. D3 toolbar/fullscreen/preview/undo, D4 management, D5 real end-to-end integration and D6 release pending. No production change.
