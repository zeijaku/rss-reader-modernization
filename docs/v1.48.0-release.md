# V1.48.0 正式版：更新・確認・復旧手順

> この文書は正式化準備資料です。GitHub Releaseを作成するまでは正式Runtime ZIP・タグは公開されていません。

## 変更概要

Remote Files機能強化。Sort、検索・種類絞り込み、複数選択、一括Delete／Move、Upload進捗・中断、階層維持Directory Upload、ZIP一括Download、ドットファイル名維持、レスポンシブUI整理。

- Application Version: `1.48.0`
- APP_ASSET_REVISION: `1.48.0`
- Database Migration: なし
- 新規必須Config: なし
- PHP ZIP拡張（ZipArchive）: ZIP一括Downloadに必要
- 新規公開エンドポイント: `public/remote_file_bulk_zip.php`

## 配置の注意点

1. 正式ReleaseのRuntime ZIPとSHA-256を確認し、`config/local.php`、DB、`var/`、現行コードと`public/.htaccess`をバックアップする。
2. 正式Runtime ZIPをアプリケーションルート基準で配置する。特に`public/.htaccess`はドット付きファイル名のまま確実に更新する。古いRemote Files Upload APIは先頭ドットを削るため、**正式版適用時に古いRemote Filesから`.htaccess`を直接アップロードしない**。専用FTPクライアント等で正しい名前のまま上書きする。
3. `public/.htaccess`に`remote_file_bulk_zip\\.php$`の許可エントリが存在することを確認する。GETで`/remote_file_bulk_zip.php`を開くと`POST is required.`となるのが正常（403は許可ルール不適用）。
4. フッターの `RSS Reader Modernization 1.48.0` 表記を確認する。キャッシュ／OPcacheにも注意する。

## 基本動作確認

- 認証／2FA、Dashboard、RSS、Calendar、File Library、Mailと既存ゲーム。
- Remote Files（FTPS中心。可能ならFTP、SFTP、WebDAVも）：List、Search、Sort、複数選択、削除（**空でないDirectoryの削除は既存仕様で不可**）、Move、通常Download、ZIP Download、通常Upload、Directory Upload、進捗、中断。
- ZIPはPHPの`ZipArchive`が有効である必要がある。ZIP一括Downloadは選択200件、合計100MB、深さ15階層などの制限がある。
- `.htaccess`、`.gitignore`はRemote Files Uploadで先頭ドットを維持する。File Libraryの既存ファイル名検証は変更しない。

## 復旧

異常が出た場合はアプリケーションコード・`public/.htaccess`をバックアップから戻す。DB Migrationは存在しないためDBスキーマ変更の巻き戻しは不要。復旧後に認証・Remote Files・RSSを確認する。

## 正式公開の順序

1. 本正式化PRの回帰CI（PHP 8.1／8.4、Apache公開エンドポイント検査）を確認。
2. PRを1回だけ`main`にMerge。
3. `main`のCIと`tools/check_release_ready.py --release 1.48.0`により正式化準備を確認。
4. `.github/release-request.txt`を`1.48.0`に更新する別PRを統合し、共通Release Workflowによるタグ／正式Release／Runtime ZIP／チェックサム生成を確認。
5. 実サーバーへ正式Runtime ZIPを配置する（特に隠しファイル`.htaccess`に注意）。

## 検証上の留意点

dev1〜dev9は利用者による基本動作確認済み。ただし全Provider・全ブラウザ・大量ファイル・全失敗経路を網羅したものではない。CIと正式Release生成の結果は別途確認する。
