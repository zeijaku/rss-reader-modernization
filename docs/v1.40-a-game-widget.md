# V1.40-A Game Widget / Maze Chase

Development checkpoint: `1.40.0-dev.2`. Formal V1.40.0 release is not requested.

## Scope

The existing `widget_type=game` / `{schema:1,title,game}` model and authenticated `widget.game.*` APIs are reused. Maze Chase is an original local Canvas game. Its engine is loaded only when a Maze Widget is present. The versioned entry passes its revision to the engine. Existing game engines and their storage keys remain unchanged. No schema, dependency, credential, production configuration, or API endpoint is added.

The new shared layer handles module loading, instance initialization/destruction, score/Best, Restart/Pause, expansion, focus boundaries and visibility. The engine owns the original maze, pellet/escape items, simple chase/random/escape sentries, collision, clear/game-over and touch direction controls. Sound is OFF. Best is per browser, user and widget, with localStorage / sessionStorage / memory fallback. Running board state is not persisted.

## Verification

- Focused PHP/PDO: strict config, multiple placements, owner isolation, prefix, invalid input, legacy subtype compatibility.
- Pure engine: reachable maze, independent state, wall/queued movement, scoring, power, enemy AI, collision, clear and long simulations.
- Chrome browser fixture: actual Dashboard/Stock Drawer catalog generation, visible Maze menu tile, Bootstrap add-modal transition and preset selection, legacy menu retention, duplicate prevention, delayed catalog initialization, PC and 360px touch layouts, one module request, inherited revision, focus boundary, user Pause, visibility, expansion/Escape, destroy, card replacement, Best reload, blocked Storage, load failure/retry and legacy engine initialization.
- Current regressions: `bash tests/run-ci.sh` (current / current features and workflow preflight).
- Optional browser test: `GAME_TEST_CHROME=/path/to/chrome node tests/test_current_game_widget_browser.js`, with Playwright available. The browser fixture is separate from a real production login/session.

## 本番確認の順序

1. 現在のVersionと対象ファイルをバックアップ。確認対象は1.39.2。差分ZIP内の`app/`・`public/`だけを同じ階層へ上書き。設定ファイルやDBを変更しない。
2. PCで再読込し、Versionが`1.40.0-dev.2`になったことを確認。RSS更新、Memo/Task/Calendar、Mailなど普段使う機能を先に確認。
3. メニューのGameを開き、Maze Chaseが1個表示されることを確認。Maze Chaseを押し、Game追加画面でMaze Chaseと初期タイトルが選択されることを確認。見出しを設定し、追加できることを確認。開始前は停止状態。
4. Startを押し、青い菱形のPlayerを矢印キー／WASDで移動。小さな粒で得点が増え、壁を通り抜けないことを確認。盤面外を選択したときは矢印キーでページが通常どおり動くことを確認。
5. 大きな菱形を取得し、敵の色が変わることを確認。有効中は敵を押し戻せること、時間経過で元に戻ることを確認。
6. 敵に触れてGAME OVERになること、RestartでScoreが0へ戻ること、Bestは残ることを確認。全Itemを集めるとCLEARになる。
7. Pauseで停止、Resumeで再開。手動Pauseのまま別ブラウザTabへ移動して戻ってもPauseが維持されることを確認。画面外へScrollすると停止する。
8. 拡大／縮小とEscapeで閉じる操作を確認。拡大中はページScrollが止まり、縮小後は戻る。拡大中のTab移動がGame内に留まることを確認。
9. Maze Chaseをもう1個追加。1個の開始・Pause・得点・Restartがもう1個へ影響しないことを確認。見出し・色・幅・高さ変更、並び替えも確認。
10. ページ再読込後のBest保持を確認。Gameを別種へ変更／削除し、旧Gameの動作が残らないことを確認。設定変更時の盤面は開始前に戻る。
11. Reversi、2048、Wire Defense、Icon Quest、Lights Out、Block Collapse、Cursor Fieldを確認。RSS Typingを使用している場合も確認。
12. Smartphoneで追加・方向ボタン・Pause・Restart・拡大を確認。盤面のはみ出し、ページScroll、DashboardのSwipeやDragとの競合がないことを確認。
13. Gameを配置していないTabで、開発者ツールのNetworkに`maze-chase.js`が要求されないことを確認。配置したTabでは現在Revision付きで1回読込まれる。

## Existing limitation

Stock already lacks the Wire Defense option in its add/change Game selects at the 1.39.2 baseline. Its menu tile exists but cannot select that subtype. This checkpoint preserves that unrelated behavior; Dashboard Wire Defense and all other legacy menu selections are verified.

## Rollback

先にMaze Chase Widgetを削除してから旧ファイルへ戻す。旧VersionはMaze subtypeを認識しないため、設定を残して戻すとIcon Questとして扱われる。Rollback ZIPは変更した既存`app/`・`public/`ファイルの1.39.2版を復元する。新規`public/js/game-widget.js`・`maze-chase.js`・`public/css/game-widget.css`を削除する。Bestの端末保存はWidget削除時に削除される。DB Migrationは不要。
