# V1.47-B P2-B：HTTPヘッダー・公開境界とCSP候補の隔離検証

> 状態：P2-B検証レポート。**本番の設定を変更する指示ではない。**
> 基準：P1確認版（PR #151、1.47.0-dev.2）を継承したブランチ。
> **本番用の .htaccess / PHP / JS / CSS / DB / config/local.php / app/version.php は変更しない。**

## 1. 目的と検証境界

現在の強制CSPおよびアクセス制御は一切上書きせず、GitHub Actions上でApache 2.4を一時起動する。
両DocumentRoot方式を模擬する。

1. **app-root**：アプリルートにDocumentRoot、ルート .htaccess でpublic/へ内部Rewrite（現行本番構成に近い）。
2. **public-root**：DocumentRootをpublic/に限定（推奨構成）。親 .htaccess の影響を受けない別ツリーを使う。

リポジトリの2つの .htaccess は**そのまま**fixtureへコピーする。
一時Apacheの設定でのみ \`Content-Security-Policy-Report-Only\` を追加する。
テスト終了時に一時ディレクトリとサーバープロセスを破棄する。

**重要な限界：検証PHPファイルは実行せず安全な固定文字列を返す。HTTP 200はApacheのルーティング結果であり、PHPの実行、認証突破、情報取得を実証するものではない。**
一時環境では意図的に \`AcceptPathInfo On\` を設定して境界条件を探索する。本番Apache/PHPハンドラーの設定値は調べていない。

## 2. 既存ヘッダーの契約

\`public/.htaccess\` の強制CSP：

\`\`\`text
frame-ancestors 'self'; base-uri 'self'; form-action 'self'; object-src 'none'
\`\`\`

既存：\`X-Content-Type-Options: nosniff\`、\`X-Frame-Options: SAMEORIGIN\`、
\`Referrer-Policy: strict-origin-when-cross-origin\`、Permissions-Policy。
JS/CSSは \`Cache-Control: public, max-age=31536000, immutable\`。
非公開HTMLやAPIのキャッシュ無効化はアプリ側のPHP処理で、既存の別テストが担当する。

隔離Apacheのチェック対象：基本ヘッダー、既存の強制CSPが変わっていないこと、
Report-Onlyが**別ヘッダー**であること、公開済みPHPパス、
未知PHP・ネストPHPの拒否、ルート私有領域の保護、非公開拡張子の拒否、
静的資産のキャッシュ挙動。
\`tests/test_current_p2b_apache_probe.py\` が実行する。

## 3. P2-Bでのみ設定するReport-Only候補

以下はあくまで検証仮説。**本番の .htaccess には追加しない。**

\`\`\`apache
Header always set Content-Security-Policy-Report-Only "script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data: https:; frame-src 'self' https://www.youtube.com; media-src 'self' https:; worker-src 'self' blob:; object-src 'none'"
\`\`\`

- \`default-src\` はこの試験案ではあえて指定せず、未棚卸しの読み込み種別を意図せず一括制限しない。
- \`style-src 'self'\` は現存するHTML \`style\`属性やエラー画面の\`<style>\`の違反を調べる目的（実際には遮断しない）。JavaScriptのDOMスタイルプロパティ設定がすべてCSP違反になると決めつけない。
- \`script-src 'self'\` は同一サイトのJSを中心にした仮説。Calendar/Game/File Library等の動的ロードを含め、実ブラウザ確認が必要。
- CameraのYouTube iframeは\`frame-src\`、外部動画とHLSは\`media-src\`／\`connect-src\`／\`worker-src\`をそれぞれ確認。Blob Worker、外部ドメイン、動画のMixed Contentなどは機能実測が必要。
- HTMLの画像、テーマCSS内のdata: SVG、RSS画像に注意。試験案の\`img-src\`はそれを踏まえた暫定的な広めの値。
- \`report-uri\`／\`report-to\`は設定しない。ユーザー情報を含むレポートをサーバーへ不用意に集めない。実ブラウザConsoleを使う検証は次段階。
- 実ブラウザへ追加ヘッダーを配信していないため、**ブラウザでのCSP違反件数は未測定**。隔離Apacheで確かめるのはヘッダーの構文・実効送出と既存強制CSPの保持まで。

## 4. 見つかった境界条件：P2-C最優先

\`public/.htaccess\` のPHP許可リストは\`*.php\`で終わるURLを対象としており、
\`AcceptPathInfo On\`を**テストサーバーに明示設定した場合**、以下の診断結果が出る。

| URL（すべてテスト用のダミーファイル） | app-root側の観察例 | 判断 |
| --- | --- | --- |
| \`/unknown.php\` | 403 | 既存制限は有効 |
| \`/nested/deep.php\` | 403 | 既存制限は有効 |
| \`/unknown.php/extra\` | 200 | **PATH_INFOで末尾\`.php$\`条件を外れる可能性** |
| \`/unknown.phtml\` | 200 | **PHP以外のサーバー実行可能拡張子が許可リストの対象外** |

これらの200は**固定文字列の静的配信結果**であり、PHPとして実行された証拠ではない。
実際の本番で危険になるかは、PHPハンドラー、\`AcceptPathInfo\`、\`.phtml\`等の関連付けに依存する。
ただし許可リストの設計上の穴になりうるので、P2-Cでは先にApacheのパス境界を防御的に修正し、
両DocumentRoot方式＋PHPハンドラー込みのテストを設計する。
他のCSP強制化より優先して評価する。

## 5. P2-Cでの優先順位

1. **公開PHPのURL境界**：未知PHP+PATH_INFOと、実行可能な別拡張子の拒否方針を設計。正常な既存URL、Download、Preview、リライトへの影響を回帰テスト。
2. **PHPレスポンスとのヘッダー合成**：Apacheヘッダーと個別PHP CSP（画像/PDFの\`sandbox\`など）が複数ヘッダーとして適切に扱われるか、実際にPHPを動かす別の隔離環境で検証する。
3. **CSPのブラウザ実測**：一時環境（本番以外）でReport-OnlyをHTMLに送出し、ログイン・Dashboard・Calendar・Mail・Remote Files・Camera・Gameを調べる。ブラウザから取得した違反を精査するまでは強制に移行しない。
4. **HSTS**：本番ドメインとサブドメインのHTTPS運用範囲が確認できるまで導入しない。
5. **API rate limit**：600/分と120/分は暫定値。別途、実測に基づいて調整する。

## 6. 変更・配布の扱い

P2-Bでは**検証コード、CIジョブ、この報告書のみ**を変更する。
アプリ実行物に変更がないため本番ZIPは不要、デプロイも不要。
PRはdraftのまま維持し、P0/P1を含めてmainへ自動マージしない。

GitHub CIは既存PHP 8.1／8.4回帰テストと、別ジョブのApache隔離検証を実施する。
P2-C以降の強制変更は**別工程で**レビューする。
