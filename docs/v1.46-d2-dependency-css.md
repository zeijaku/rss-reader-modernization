# V1.46-D2 Dependency / CSS Finishing

Implementation date: 2026-10-08

## Scope

V1.46-D2 deliberately keeps the dependency change narrow and performs low-risk CSS consolidation.

Visible release version remains V1.45.0. The development asset revision is `1.46.0-dev.4`.

## hls.js

### Update

- previous: hls.js 1.6.16 loaded from pinned jsDelivr URL with SRI
- current: hls.js 1.7.3 vendored as `public/js/hls-1.7.3.min.js`
- loading remains lazy and HLS-Widget-only
- the local child asset inherits the active application asset revision
- Native HLS fallback remains available
- bounded network/media recovery and teardown behavior remain unchanged

The vendored file was extracted from the official GitHub hls.js v1.7.3 `release.zip`, not copied from an arbitrary mirror.

## Drawer CSS consolidation

Before D2 the active Drawer organizer injected three stylesheets:

1. `drawer-v121b.css`
2. `drawer-v121c.css`
3. `drawer-catalog.css`

D2 consolidates those rules into `public/css/drawer.css` in exactly the same cascade order.

`drawer-categories.js` now injects one revision-aware `drawer.css` link.

This is a packaging/maintainability cleanup, not a Drawer redesign. Existing visual hierarchy, Smartphone safe-area handling, touch targets, Widget Catalog layout and reduced-motion behavior are retained.

## Calendar CSS consolidation

Before D2, Calendar loaded:

- `calendar-polish.css`
- `calendar-polish-r3.css`
- `calendar-deadline.css`

D2 appends the R3 rules to `calendar-polish.css` and removes the separate R3 stylesheet request.

`calendar-deadline.css` intentionally remains separate because it represents an independent current behavior and contains its own animation/reduced-motion contract.

The JavaScript module `calendar-polish-r3.js` also remains separate; D2 only removes an unnecessary CSS cascade layer.

## Removed runtime files

These files are no longer referenced by Current runtime:

- `public/css/drawer-v121b.css`
- `public/css/drawer-v121c.css`
- `public/css/drawer-catalog.css`
- `public/css/calendar-polish-r3.css`

An overwrite-only production verification does not require their immediate deletion because no Current loader references them. They should be removed when synchronizing the server to the final release inventory.
