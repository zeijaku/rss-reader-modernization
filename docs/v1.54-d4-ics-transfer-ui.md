# V1.54 D4 — Calendar transfer UI and integration

Existing Calendar management modal has a third Import / Export tab. No new widget buttons. Local sources only; existing source list API and authenticated transfer API reused. Import fields use FormData with UTF-8 text (8 MiB); options invalidate approval, explicit confirmation required, busy state prevents tab/modal closing during request. Server HMAC still authoritative. Preview shows add/update/skip/unsupported/conflict and owner-level date mark counts and reasons. User-provided labels are text nodes. On uncertain result re-preview, never retry automatically. On success refresh source list and visible calendars via existing events. Export uses bounded response Blob with safe filenames and delayed URL revocation. Mobile layout uses stacked fields, 44px controls and scrollable details. ZIP import unsupported.

Tests: D1-D3 focused regression plus real authenticated multipart HTTP round trip using SQLite fixture, foreign-source and CSRF guards, stale token, ZIP verification and request-size isolation; DOM contract always runs, desktop/touch 360px Chromium test follows the existing optional GAME_TEST_CHROME browser convention. Actual iOS/Android device and third-party calendar services not certified. PHP post_max_size must exceed 8 MiB plus multipart overhead. No Memo changes, new migration, production deploy or version bump.
