# ICS購読 Dev1.1 — Calendar管理 UI統一

## 目的
Dev1（`1.51.0-dev.1`）でICS登録・Google Calendarからの取得（例: 1,756 bytes）を確認した後、画面のわかりやすさを改善する補修版です。
**ICS取得/DB/URLの秘匿処理・Calendarの予定表示APIは変更しません。** Dev2では引き続きVEVENT解析とCalendarへの予定表示を行います。

## UI変更
- 「Calendar管理」をBootstrapテーマに沿った青いヘッダー・統一されたフォーム・パネル構成に変更（既存の予定登録・変更画面と統一）。
- 「通常Calendar」／「外部ICS購読」の2タブ。既存のCalendar追加・変更・削除フォームとイベントハンドラは維持。
- ICS「今すぐ取得」を通常時に青枠ボタン、処理中はスピナー＋「取得中…」およびdisabled/aria-busyで重複クリックを防止。
- ICS取得結果を「取得成功」「取得失敗」「未取得」の3色バッジと詳細・最終確認日時に分けて表示。
- 取得先ホストのみ表示、非公開URLのpath/queryは表示しない。ICS色識別は予定入力UIと同じマットな15px四角マーカー。
- 通常CalendarとICSのリスト・ボタン・余白・モバイルレイアウトを整理。Bootstrapの`nav-tabs`相当のデータ属性を使い、専用の切り替えロジックは作らない。

## 更新
対象：**`v1.51.0-dev.1`をすでに適用した環境のみ**。
`RSS_Reader_V1.51_Dev1_1_Calendar_Manager_UI_Update.zip` をアプリケーションルートに展開し、記載の4ファイルを上書きしてください。ZIP内のディレクトリ構造は維持します。

- `app/version.php`
- `app/view/dashboard_modals.php`
- `public/js/calendar-ics.js`
- `public/css/calendar-ics.css`

今回の更新では**SQLの実行やDB移行は不要**です。既存Dev1のMigration 035および登録済み購読URL・キャッシュはそのまま使います。
Dev1からの差分だけであり、単独でv1.49.1／v1.50 Dev16には適用できません。

## 動作確認
1. Calendar管理を開く → 「通常Calendar」「外部ICS購読」のタブを切替。マウス・キーボード両方を確認。
2. 通常Calendarで既存の追加・変更・削除、既定Calendar削除不可の状態を確認。
3. ICSで既存購読一覧と「取得成功」バッジ・最終確認日時を表示。色の四角が出ることを確認。
4. 「今すぐ取得」クリック後に「取得中…」+スピナー、完了後に取得成功バッジとbyte数が残ることを確認。
5. URLの変更・再取得・削除が動作し、非公開ICS URLやキャッシュ本文が画面・APIレスポンスに露出しないことを確認。
6. スマートフォン幅でフォーム/ボタンの折り返し、既存Calendar予定の追加・変更への影響がないことを確認。
