# V1.12-E RSS Highlight finalization

## Scope

V1.12-E closes the RSS Highlight part of Version 1.12 before Mail Phase 2 begins.

No new Highlight feature is added in this checkpoint. The V1.12-D rendering behavior is retained and the implementation boundary is verified.

- RSS Widget titles use the shared Highlight renderer.
- Search Feed titles use the same shared renderer.
- Keyword create/delete continues to update visible titles without a page reload.
- Highlight markup stays display-only.
- Stock / Task / article Actions continue to use the original plain title string.
- Mail remains unchanged.
- No additional database migration is added.

## Final Highlight behavior

The initial V1.12 RSS Highlight feature is considered complete with the following behavior.

- User-owned keywords are stored in `feed_keyword`.
- Up to 50 active keywords per user.
- Up to 64 characters per keyword.
- Partial title matching.
- Multiple matches in one title.
- Latin alphabet matching is case-insensitive.
- RegExp metacharacters in a keyword are treated as literal text.
- Longer keywords are preferred when alternatives can start at the same position.
- A single common highlight color is used.
- RSS Widget and Search Feed share the same rendering path.

## Security / data boundary

Highlighting does not turn RSS title strings into HTML.

`renderFeedKeywordTitle()` clears only the displayed title node and rebuilds it with `document.createTextNode()` and `<mark class="feed-keyword-highlight">`. The original title remains in the existing plain-string attributes/data used by article Actions and related features.

The keyword bootstrap data remains JSON in `script[type="application/json"]`, generated with the JSON hex escaping flags introduced in V1.12-C.

## Database

No V1.12-E migration is added. The only RSS Highlight migration remains:

- `database/migrations/012_v1_12_feed_keywords.sql`

Existing RSS / Search Feed / Stock / Mail rows are not modified by V1.12-E.

## Focused finalization checks

- PHP syntax for the Highlight backend/API/bootstrap/index/version files.
- JavaScript syntax for `public/js/dashboard.js`.
- Exact Highlight matching cases: multiple keywords, case-insensitive Latin matching, metacharacters, Japanese text, longer same-position priority.
- DOM renderer still uses TextNode + mark and does not use `.html()` for Highlight.
- RSS Widget fetch and Search Feed fetch both end at `renderFeedItems()`.
- Article Actions keep `data-article-title` from the original item title.
- No new database migration after `012_v1_12_feed_keywords.sql`.
- Distribution excludes `vendor`, `config/local.php`, `.env`, runtime logs/caches and nested ZIP files.

## Next step

RSS Highlight is complete for the initial V1.12 scope. The next development checkpoint can start Mail Phase 2 while preserving the current read-only Mail safety policy.
