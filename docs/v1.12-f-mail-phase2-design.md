# V1.12-F Mail Phase 2 設計・影響範囲確認

## 目的

V1.12後半では、V1.9で導入済みのMail Widgetを「読み取り専用」のまま使いやすくする。
メール送信、削除、移動、既読/未読変更など、IMAPサーバー上の状態を書き換える機能は追加しない。

V1.12-Fでは設計確認のみ行い、Mailの実行ロジック・UI・API動作は変更しない。

## 現状確認

### Mail取得

`app/mail/mail_widget.php` の `mail_widget_read_latest()` は現在INBOX固定。

- `EXAMINE('INBOX')` を使用
- `MessageQuery` を直接生成
- `withHeaders()` / `withFlags()`
- `leaveUnread()`
- `newest()`
- 表示件数は5件または10件
- `!$message->isSeen()` から各メールの `unread` を返す

このため、一覧取得では既読化を行わない設計になっている。

### 本文Preview

`mail_widget_read_message_text()` もINBOX固定で、以下を維持している。

- `EXAMINE('INBOX')`
- `leaveUnread()`
- BODYSTRUCTUREのみ先に確認
- text系かつ添付ではないMIME Partのみ対象
- `bodyPart(..., true)` によるPEEK取得
- 256 KiBを超えるPartは取得しない
- ブラウザへ渡す本文は最大20,000文字
- HTML本文を直接表示しない

Phase 2でもこの安全境界は変更しない。

### 現在すでにあるUX

`public/js/mail-widget.js` には以下が既にある。

- 未読メールの行強調 (`mail-unread`)
- 未読ドット
- Widget単体更新ボタン
- 本文の遅延Preview
- Account切替・管理

したがってPhase 2で未読強調と単体更新を再実装しない。

## DB方針

### 新規Migration

V1.12 Mail Phase 2では **新規DB Migrationなし** を基本方針とする。

Mail Widget設定は既存 `dashboard_widget.widget_config` のJSONに保存されている。
現在のschema 1は次の内容。

```json
{
  "schema": 1,
  "title": "Mail",
  "item_limit": 5
}
```

Folder選択を永続化する段階でschema 2へ拡張する。

```json
{
  "schema": 2,
  "title": "Mail",
  "item_limit": 5,
  "folder": "INBOX"
}
```

schema 1を読み込んだ場合は `folder = INBOX` とみなして後方互換を維持する。
既存レコードのUPDATE Migrationは行わない。

### 保存しないもの

以下はWidgetの一時表示条件とし、初期Phase 2ではDBへ保存しない。

- 未読のみ表示ON/OFF
- 件名/From検索文字列
- 送信者Filter
- 最終更新日時

ページ再読込でリセットされてよい。

## V1.12-G: 未読UX

実装対象:

1. 選択Folderの未読件数表示
2. 「未読のみ」表示切替
3. 最終更新日時表示

### 未読件数

表示中5/10件の中だけを数えた値を「未読件数」とは呼ばない。
可能な限り選択Folder全体の未読数をサーバー側で取得して返す。

実装時は、実運用で導入されているImapEngineの利用可能APIを確認して、read-onlyの検索/STATUS相当で取得する。
ライブラリに適切なAPIがない場合、独自IMAPコマンド文字列を安易に組み立てない。

APIレスポンス予定:

```json
{
  "messages": [],
  "unread_count": 12,
  "fetched_at": "2026-08-10T11:30:00+09:00"
}
```

`fetched_at` はRSS Readerサーバーが取得完了した時刻であり、メールサーバー上の更新時刻ではない。

### 未読のみ表示

V1.12-G初期版ではブラウザ側Filterとする。
一覧取得済みデータの `message.unread` を使い、サーバーへの追加書き込みは発生しない。

## V1.12-H: 件名 / From検索・送信者Filter

実装対象:

- 件名検索
- From検索
- 送信者Filter

### 基本方針

検索は最終的にサーバー側IMAP検索を優先する。
ブラウザに取得済みの5/10件だけを検索して「メール検索」と見せる実装は避ける。

検索条件は固定された種類だけを許可する。

- subject
- from

検索値をIMAPコマンド文字列へ直接連結しない。
利用中ImapEngineのQuery Builder/APIが提供する安全な検索方法を使う。

### 送信者Filter

初期版では検索結果/取得結果に含まれる `from_email` / `from_name` を利用したUIを想定する。
必要以上に巨大な送信者一覧を取得・永続化しない。

## V1.12-I: Folder切替

Phase 2で最も慎重に実装する。

### Folder一覧

ブラウザが自由なFolder名を入力する方式にはしない。

1. IMAPサーバーからFolder一覧を取得
2. サーバー側で表示可能なFolder名として整形・上限制御
3. ブラウザへ候補として返す
4. ユーザーは候補から選択
5. fetch/message APIでも、そのFolderが許可済み候補か再確認
6. `EXAMINE(folder)` でread-onlyアクセス

### UIDとFolder

IMAP UIDはFolderごとに意味を持つため、本文取得は `widget_id + folder + uid` の組で扱う。

現在の `mail.widget.message` は `widget_id + mail_uid` のみでINBOX固定なので、Folder切替時に必ず拡張する。

ブラウザから渡されたFolder名を信用して、UIDだけで本文を取得しない。

### 設定保存

選択Folderは `widget_config.schema = 2` の `folder` に保存する。
既存schema 1はINBOXとして扱う。

Focused回帰対象:

- INBOX既存表示
- 未読行強調
- 未読件数
- 未読のみ表示
- 最終更新日時
- 件名検索
- From検索
- 送信者Filter
- Folder切替
- Folder切替後の本文Preview
- Widget単体更新
- Account変更後の再取得
- 5/10件制限
- SP表示

安全境界も再確認する。

- SELECTを使用しない
- EXAMINEを維持
- `\\Seen` を付与しない
- STORE/COPY/MOVE/DELETE/EXPUNGEを追加しない
- SMTP/送信処理を追加しない
- HTML Mailを直接DOMへ入れない
- 外部画像をロードしない
- 添付ファイルを取得しない
- Mail本文をDBへ保存しない
- IMAP資格情報をブラウザへ返さない
- SSRF対策のhost validation / DNS pinning / TLS検証を維持
