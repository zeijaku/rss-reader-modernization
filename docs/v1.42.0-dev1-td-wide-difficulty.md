# V1.42.0-dev1: Tower Defense 広域マップ・難易度

Application / Asset Revision: `1.42.0-dev.1`。

Base: `fix/v1.41.1-calendar-deadline-pulse`（V1.41.1-dev.1 / Draft PR #120）。
V1.41.0 `main` から直接分岐せず、Calendar修正を親にしてVersion / Asset Revisionの競合を避ける。Calendar側がmainへ入った後、TD PRのbaseをmainへ切り替えてTD差分だけを確認する。

## Stage layout

- Stage 1–3: V1.41.0の12×8・単一路線を維持。
- Stage 4–6: 24×8の広域盤面。各Stageに2入口・2経路を固定。
- 2経路は大部分を上下に分離し、拠点直前だけ短く合流する。中央帯の岩で両経路を1か所からまとめて攻撃しにくくする。
- Stage 4–6はEasyを含む全難易度・全Waveで両入口を使う。Wave 4 / 8は両入口からBossを投入する。
- Map / Route / RockはStageに固定し、難易度・カード幅・拡大表示・プレイ中Resizeでは変化させない。

## Board sizing

通常盤面は従来どおりCard幅に合わせて最大540px。広域盤面は1Tile約45pxを維持するため1080×360pxを論理サイズとする。

- 2列幅PC: 広い範囲を一度に確認しやすい。
- 1列幅PC / Smartphone: `.td-board-scroll` 内だけ横Scroll。
- Document全体には横Overflowを出さない。
- TDの拡大表示だけ最大1180pxへ広げ、既存Game Widgetの拡大/縮小Lifecycleを使う。

## Difficulty

| Difficulty | Start Gold | Base HP | Enemy HP | Speed | Spawn gap | Enemy count | Reward |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Easy | 300 | 24 | ×0.85 | ×0.94 | ×1.15 | ×0.84 | ×1.08 |
| Normal | 220 | 20 | ×1.00 | ×1.00 | ×1.00 | ×1.00 | ×1.00 |
| Hard | 190 | 16 | ×1.12 | ×1.05 | ×0.86 | ×1.08 | ×0.95 |
| Nightmare | 165 | 12 | ×1.24 | ×1.10 | ×0.72 | ×1.16 | ×0.90 |

NormalはV1.41.0の15% HP増加を基準として維持する。Hard/NightmareはHPだけでなく資金・拠点HP・敵数・編成開始Wave・速度・出現間隔も厳しくする。Easyは強敵投入を遅らせる。

★判定は各Difficultyの最大拠点HPに対する80% / 40%を境界にし、Normalでは従来の16 / 8と一致する。

## Save migration

新規save schemaは2。

- checkpoint: stage / difficulty / wave / phase / health / gold / score / towers。
- bests: 6 Stage × 4 Difficultyの★。
- V1.41.0 schema 1はNormalとして移行。
- 旧6 Stageの★は各StageのNormalへコピーし、他Difficultyは未クリアから開始。
- 旧checkpointは検証後にNormalとして復元。
- Stage 4–6の新Roadと重なる旧Towerだけ、種類・Lv・spentを維持したまま最寄りのbuildable cellへ決定的に移動。
- V1.41.0の既存`.state` keyは**上書きしない**。新進行は`.state.v2`へ保存し、元schema-1 payloadもschema 2の`legacyV1`へ保持する。Code rollback時は旧版が旧`.state`をそのまま読める。
- Widgetを明示的に削除した場合だけ、Game Widget cleanupが旧`.state`と新`.state.v2`の両方を削除する。
- 戦闘中に閉じた場合は従来どおりWave開始直前checkpointから再開。
- Browser localStorage / sessionStorage fallbackを維持。端末間同期なし。

## Production playtest

1. Stage 1–3が従来感覚で遊べる。
2. Stage 4–6を横2列Cardで確認し、上下2経路へ塔を分散しないと突破されやすいことを確認。
3. 同じStageをEasy / Normal / Hard / Nightmareで開始し、Map/Routeが変わらず資金・HP・敵圧だけ変わることを確認。
4. Smartphone / 1列Cardで広域盤面を左右Scrollし、Tileが極端に小さくならず配置できることを確認。
5. Stage/Difficultyを保存してReloadし、同条件へ復帰することを確認。
6. V1.41.0 saveがあるBrowserでNormalへ移行し、旧★と配置が失われていないことを確認。
7. 1Play 5〜10分を目安に、Easyが単調すぎないか、NightmareがHPだけの壁になっていないか、合流地点だけの集中配置で全Stageを突破できないかを実プレイで調整する。

正式Release / Production反映はこのCheckpointに含めない。


## Rollback

Code rollbackはV1.41.1-dev.1のRuntime 5 filesへ戻す。新TDは旧`.state`を上書きせず`.state.v2`へ保存するため、V1.41系のCodeへ戻すと旧TDは元のschema-1保存をそのまま再読込できる。`.state.v2`は残っていてもV1.41系Codeから参照されない。Widget自体を削除した場合だけ両keyを削除する。
