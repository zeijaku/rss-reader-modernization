# V1.51.0 正式版：ICS購読／Calendar連携 — 更新・検証・復旧手順

## リリース対象
v1.49.1を起点に、利用者が動作確認した開発版v1.51.0-dev.1〜dev.4の**ICS関連のみ**を統合します。開発中のv1.50系Precision SniperやそのほかのGameコードは含まれません。
Application Version / Asset Revision: `1.51.0`。Runtime ZIPとComplete Source ZIPは既存のRelease Workflowで作成・署名・検証します。

追加機能：
- 外部Google/OutlookなどのHTTPS ICS URLを、ユーザー単位で最大10件まで購読・管理。通常Calendar管理とICSを2タブに分ける。
- ICSを読み取り専用として月・週・日へ統合、通常CalendarとICSをソースフィルターで表示切替。ローカル予定の編集・削除・ドラッグ機能はそのまま維持。
- DTSTART/DTEND、終日、UTC/TZIDの主要変換、RRULE（日／週／月／年）、EXDATE/RDATE/RECURRENCE-IDによる主な繰り返し・例外を解析。
- **30分期限**でICSキャッシュを自動取得（Calendarを開いている場合）。Calendarの更新ボタンも手動取得を試す。最短60秒間隔。通信失敗時は最後に取得できた予定を表示し続ける。
- APIへICSの非公開URL全文や本文を返さず、SSL/TLS検証、SSRF対策、HTTPサイズ上限を維持。

## 既存環境のDB変更（Migration 035）
**v1.49.1等から初めてICS購読を導入する場合のみ、次のSQLが必須**です。

`database/migrations/035_v1_51_calendar_ics_subscription.sql`

1. 現在のDBスキーマとコード・設定・アップロード/varをバックアップ。
2. SQL先頭の `SET @table_prefix = 'ig_';` を既存環境の `DB_TABLE_PREFIX` に置き換えてから既存DBへ適用。
3. 作られた `<prefix>calendar_ics_subscription` が存在することを確認。既存の `calendar_event` / `calendar_source` のデータは変更されません。
4. v1.51.0-dev.1以降を導入済みでMigration 035も適用済みなら**再実行しない**。Migration 035の追加テーブルは独立管理です。
5. Fresh Installは `database/schema.sql` を空DBへ1回実行するだけ。**既存DBへschema.sqlを再実行しない**。

## Runtime ZIP適用
1. GitHub Release v1.51.0から正式Runtime ZIPとその`.sha256`、必要に応じてComplete Source ZIPを入手。
2. GitHub公開されたファイルをSHA-256で照合し、別ディレクトリへ展開する。
3. アプリルートに対してコード・`vendor`を更新し、`config/local.php`、`var/`、DB、利用者アップロード、秘密鍵/認証情報を上書き・削除しない。旧コードと設定をバックアップしてから作業する。
4. OPcacheとブラウザキャッシュを更新し、フッターに `RSS Reader Modernization 1.51.0`、JS/CSS `?v=1.51.0` を確認。
5. 現在v1.51.0-dev.4を導入済みの場合、DBはそのままで、実装本体は同じICS仕様です。正式版ZIPへ更新しても初期化・ICSの再登録は不要です。

## 実運用チェック
1. Calendar管理を開き「通常Calendar」と「外部ICS購読」を切替。既存の「Savage Factory」等の購読が残り、秘密URL全文が表示されないことを確認。
2. 外部ICSの取得済みbytesと最終確認を確認。月／週／日、ICS表示フィルター、予定の読み取り専用詳細を確認。
3. Google側でテスト予定を追加／削除し、前回取得から60秒以上後にCalendarの「更新」を押す。ICS発行側に変更が配信済みなら追加／削除が反映されること。
4. ページを開いている間はCalendar初回表示と約3分ごとのチェックで、**最後の取得から30分経過**したICSを再取得。閉じている間に常駐処理は行わない。
5. 通信失敗時はICS管理の「取得失敗」「前回の予定を表示中」を確認。過去の正常キャッシュを消さず、通常予定の表示は維持。
6. 通常Calendarの予定CRUD、終日・複数日・繰り返し・Occurrence別変更、Task、通知、RSS/Reader Mode、Stock、Remote Files、Mail、Game、ログインと2FAを簡単に確認。
7. スマートフォンとPC、ライト/ダークThemeも確認。

## 仕様上の制限
ICS発行元（Google/Outlook等）の反映には時間差があり、RSS Readerが再取得しても最新になるとは限りません。30分は自動取得期限であり、ページを閉じたまま30分ごとのサーバー実行はしません。RFC 5545の独自VTIMEZONEや高度なRRULE（BYWEEKNO/BYHOUR等）は一部未対応。外部予定の編集・削除やRSS ReaderのICS URL公開は対象外です。

## ロールバック
不具合時はバックアップ済みの旧コード／`vendor`／設定を復旧し、DBや保存済みユーザーデータを保全。Migration 035で作成した独立テーブルは**明示的な判断なしに削除しない**でください。旧版はICSを参照しないため、表示が必要ならv1.51.0へ戻す前に原因を確認。既存の通常Calendarイベント表は変更していません。
