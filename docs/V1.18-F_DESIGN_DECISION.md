# V1.18-F Design Decision

## Decision
V1.18 will **not** add an external Internet reachability probe or a speed/throughput test.
The Connection Monitor remains a lightweight same-origin measurement of:

`Browser / device -> this RSS Reader endpoint`

This is a deliberate scope decision rather than unfinished implementation.

## Why external Internet probe is not included
An external target changes the question being measured. A request to a third-party host
measures `Browser -> third party`, not `Browser -> RSS Reader`. A result could therefore
show the Internet as healthy while the RSS Reader route is unhealthy, or the opposite.

It would also introduce one or more of the following:
- third-party service availability as a new dependency;
- cross-origin/CORS/browser-policy differences;
- privacy and traffic disclosure to a third party;
- target-selection and abuse/SSRF-like design questions if arbitrary URLs were allowed;
- extra background traffic unrelated to the RSS Reader's own reachability.

V1.18 therefore keeps `./connection_probe.php` as the only direct health probe target.

## Why speed test is not included
A meaningful throughput test requires transferring substantially more data than the current
204 probe. Running that periodically would be inappropriate for a dashboard widget because it
can consume server bandwidth, mobile data, and hosting transfer quota while also perturbing the
connection it is trying to measure.

Even a manual speed test would be a different feature from reachability/latency monitoring and
would require its own payload size, cancellation, rate-limit, cache-control, mobile-data warning,
and server-capacity design.

## What remains in V1.18
- same-origin GET `./connection_probe.php`;
- 5-second foreground polling with no overlap;
- pause while the tab is hidden and immediate resume on visibility return;
- current HTTP RTT latency;
- 30s / 60s / 5m in-memory history;
- Avg / Max / HTTP RTT variation (Jitter label);
- disconnect confirmation, recovery, downtime and last disconnect;
- Excellent / Good / Fair / Slow / Offline;
- recent median baseline and conservative relative-slow indication;
- shared page-level probe stream for multiple Connection Monitor widgets.

## Explicit non-goals locked for V1.18
- no arbitrary probe URL;
- no fixed Google/Cloudflare/public-IP probe;
- no ICMP/ping emulation claim;
- no client/local IP discovery;
- no WebRTC address discovery;
- no automatic or manual bandwidth/speed test;
- no external JavaScript/chart/monitoring dependency;
- no DB/localStorage history persistence.

## Future option
If a throughput feature is wanted later, it should be designed as a separate, explicit manual
feature (not a background monitor), with a same-origin endpoint, bounded payload, rate limiting,
clear transfer-size disclosure, cancellation, and mobile-data safeguards. It should not be
silently added to Connection Monitor polling.

## Release Gate
V1.18-F does not run the full regression suite. Full regression and final release packaging remain deferred to V1.18-G Release Gate.
