# V1.47.0 正式版：更新・確認・復旧手順

> この文書は正式公開の準備資料です。**Draft PRの段階ではまだタグ／GitHub Releaseは存在しません。**
> V1.46.0からの更新と、V1.47-B開発確認版（dev.2／dev.3）からの更新の両方を想定します。

## 変更概要

V1.47.0はSecurity Releaseです。APIレート制限、平文FTPの運用ポリシー、共通例外ログの情報最小化、ApacheのPHP URL境界強化を行います。既存の23公開PHPエンドポイントのファイル名と主要機能は維持します。

```text
Application Version  1.47.0
APP_ASSET_REVISION    1.47.0
Database Migration   なし
新規必須Config        なし
新規任意Config        APP_REMOTE_PLAINTEXT_FTP_ENABLED / APP_API_RATE_*
追加CSP強制           なし（既存の基本CSPを維持）
HSTS強制              なし
```

## 実行前チェック

1. 正式公開されたGitHub Releaseの**Runtime ZIPとSHA-256**を使用する。P0/P1/P2-Cの試験用差分ZIPを正式版と混同しない。
2. 現在のアプリケーションコード、`config/local.php`、データベース、`var/`をバックアップする。特に`public/.htaccess`、`public/api_v1.php`、`app/version.php`を確認する。
3. 本番のPHP、Apacheの`mod_rewrite`／`mod_headers`、`.htaccess`の適用状態、`var/security/`の書込み可能性を確認する。ブラウザから`config/`や`var/`を開いて中身を表示させない。
4. `config/local.php`にFTPを禁止する設定がある場合は残す。デフォルトはFTP許可（従来互換）だが、平文FTPには漏洩リスクがある。

## 配置

1. 正式Runtime ZIPをアプリケーションルートへ相対パスを保持して展開する。古い`app/`と`public/`を混ぜないよう、同一正式版を一式適用する。
2. `config/local.php`、個別の環境秘密情報、DB、`var/`を上書き・削除しない。既存DBへ`database/schema.sql`は再実行しない。
3. 正式Runtime ZIPの配置後、OPcache／ブラウザをリロードし、フッターが`RSS Reader Modernization 1.47.0`になっていることを確認する。
4. 本番運用に合わせて、必要な場合だけAPIレート制限の設定を調整する（下記）。

## 変更点ごとの確認

- **認証と表示**：Login、2FA、Dashboard、Stock、Settings、Navigation／Drawer、ログアウト。
- **RSSと生産性**：登録RSS、Search Feed、All RSS、Calendarの取得・登録・変更・Notification、Task／Memo。
- **ファイルとメール**：File Libraryのアップロード・Download・PDF Preview、Remote Files／Remote Editor、SFTP／FTPS、Mailの接続・取得・送信。
- **Gameとメディア**：Gameの起動・保存・ステージ移行、Camera／YouTube／MJPEG／HLSを利用する場合は再生。
- **セキュリティ**：通常URL`/`、`/stock`、`/settings`、`/rss-management`、`/file-library`、`/remote-files`、`/remote-editor`で予期しない403/404/500がないこと。
- **429**：通常利用で意図しないHTTP 429が出ていないこと。確認のために本番へ大量リクエストを送らない。
- **CSP**：厳格な新ポリシーは今回導入していない。ブラウザConsoleの新しいブロック／表示不具合がないことを確認する。Report-OnlyはCI隔離環境のみ。

## APIレート制限の扱い

| 設定 | 既定値 | 運用上の意味 |
| --- | --- | --- |
| `APP_API_RATE_LIMIT_ENABLED` | `true` | 認証済みAPI制限を有効化 |
| `APP_API_RATE_WINDOW` | `60` 秒 | 集計時間 |
| `APP_API_RATE_TOTAL_MAX` | `600` 回 | ユーザーごとのAPI合計 |
| `APP_API_RATE_NETWORK_MAX` | `120` 回 | 外部通信系として分類したActionの追加上限 |

これらは**実測による最適値ではなく、従来互換を優先した初期値**です。全体／Networkの2つのBucketがあり、Network系も全体Bucketを消費します。単一ユーザー・共有ストレージを想定したカウンターであり、IP／全体負荷対策の代替ではありません。連続429が実運用で発生したときはリクエストの性質と頻度を調べ、理由を記録したうえで調整します。

任意設定は既存`config/local.php`または環境変数で行えます。`false`にして完全無効化することもできますが、セキュリティ効果が失われるため一時切り分け以外では推奨しません。

## ロールバック

1. 本番運用でログイン不能、通信不能、広範囲の403/404/500などが発生した場合は公開を停止し、作業前の**アプリケーションコードと`public/.htaccess`**を復元する。
2. 今回はDB Migrationがないため新しいSQLを逆適用する作業はない。ただしデータバックアップを保持し、確認版の状態と混在させない。
3. `var/security/api-throttle/`はファイルベースの短期カウンター。原則として個別ファイルを手動編集せず、運用上の必要があれば責任者がアクセス状態を確認して復旧する。
4. 旧バージョンの復元後、フッターとログイン・RSS・Calendar・Mail・Remote Filesの基本動作を再確認する。

## 検証の範囲と未対応事項

- GitHub ActionsはPHP 8.1／8.4の現行回帰テストと、両DocumentRoot構成を模擬するApache検証、Apache＋PHPのCSP応答検証を通す。
- すべての本番レンタルサーバー設定、PHPハンドラー、実際の同時アクセス量、全ブラウザ環境までは再現していない。
- より厳格なCSP、HSTS、本番負荷に基づくAPI閾値の見直しは専用工程へ繰り越す。
- 開発確認版P0/P1/P2-Cは利用者による基本動作確認済みだが、全機能の完全な網羅確認ではない。

## 正式公開の順序

1. V1.47.0正式化PRのPHP 8.1／8.4回帰CIを確認。
2. 正式化PRを**1回だけ**`main`に統合する。P0 #146、P1 #151、P2-B #152、P2-C #153は累積ブランチなので、別々に重複統合しない。
3. `main`のCI成功を確認し、リリース用`.github/release-request.txt`を`1.47.0`に変更する**別PR**を作成・統合（または正規Workflowを明示的にDispatch）する。
4. 共通Release Workflowが`tools/check_release_ready.py --release 1.47.0`、再テスト、secret scan、Runtime／Complete Source ZIP、SHA-256、Attestationを検証した後に`v1.47.0`タグとGitHub Releaseを生成する。
5. **GitHub Release公開と本番適用は別工程**。両方を自動で同時に行わない。
