# V1.45.0 正式版

Feed CategoryをRSS管理、全RSS新着、Search Feed、OPMLへ一貫して接続するFeature Releaseです。Application Version / Asset Revision は `1.45.0`。V1.44.0からのDatabase Migrationと必須Config変更はありません。

## 適用

1. Application、`config/local.php`、Database、private runtime dataをバックアップします。
2. GitHub Releaseの正式Runtime ZIPとSHA-256を確認します。
3. Runtime ZIPを既存Applicationへ展開し、既存`config/local.php`、Database、private dataを維持します。
4. V1.45.0では追加Migrationを実行しません。
5. 既存Databaseへ `database/schema.sql` は再実行しません。Fresh InstallではCurrent `schema.sql` を使用します。
6. OPcache / Browser cacheを更新し、Footer等のVersionが `1.45.0` であることを確認します。

`APP_ASSET_REVISION` も `1.45.0` へ更新されるため、V1.45-C確認時に問題となった旧Dashboard JavaScript cacheは正式ReleaseではVersion keyによって分離されます。

## Feed Category

- Categoryは記事ではなくRSS Feedへ紐付けます。
- RSS管理でFeedごとにCategoryを設定・解除出来ます。
- Category管理からRename / Deleteが出来ます。DeleteはFeedを削除せず未分類へ戻します。
- 登録RSS一覧を `すべて` / `未分類` / 任意Categoryで絞り込めます。
- Category専用Tableは作成せず、既存 `feed_metadata.category_path` を使用します。

## All RSS Recent

- 全RSS新着の追加／変更画面でFeed Categoryを選択出来ます。
- Category指定時は対象Feedを先に絞り、その後RSSを取得します。
- 旧WidgetはCategory未指定として `すべて` 互換です。
- `未分類`、hierarchical Category、実Category名 `all` を区別します。

## Search Feed

- 「自分のRSS Category」と既存の「共通RSSカテゴリー」を独立して指定出来ます。
- 検索範囲が「自分の登録RSS」ではowned Categoryだけを使用します。
- 「共通RSS」ではowned Categoryを使用しません。
- 「両方」ではowned / commonそれぞれのCategory条件を独立して適用します。
- 旧Search Feed Widgetはowned Category `すべて` 互換です。

## OPML

- nested outline hierarchyをFeed Categoryとして維持します。
- flat OPMLでは標準 `category` 属性の先頭Category pathを採用します。
- Exportはnested hierarchyに加え、Category設定済みFeedへslash形式の `category` 属性を出力します。
- 未分類FeedにはCategory属性を付けません。
- 既存登録URLの再ImportはDuplicate扱いとし、現在Categoryを上書きしません。

## 確認

1. RSS管理で複数Feedへ異なるCategoryを設定出来ること。
2. `すべて` / `未分類` / Category指定で登録RSS一覧を絞り込めること。
3. Category Renameが対象Feedへ反映されること。
4. Category Delete後もFeedが残り、未分類へ戻ること。
5. 全RSS新着でCategoryを指定し、対象CategoryのFeed由来だけが表示されること。
6. 全RSS新着を `すべて` に戻すと従来どおり全登録RSSが対象になること。
7. Search Feedで「自分のRSS Category」を保存後、再編集して同じ値が保持されること。
8. Search Feedの「自分のRSS Category」と「共通RSSカテゴリー」が独立して動くこと。
9. OPML ExportでCategory階層と `category` 属性が出力されること。
10. ExportしたOPMLを再Importすると既存FeedはDuplicate扱いになり、現在Categoryが変わらないこと。
11. 既存RSS、Feed Health、RSS Rules、Stock、Calendar、Mail、Remote Files、Game等が従来どおり動作すること。

## Database / configuration

- Migration: なし。
- 新規Table / Column: なし。
- 必須Config変更: なし。
- PHP 8.1+ / MySQL・MariaDB。

## 公開

正式化PRをPHP 8.1 / PHP 8.4 CI通過後mainへmergeし、main CI確認後に `.github/release-request.txt` を `1.45.0` へ更新する公開PRをmergeします。共通Release WorkflowがRuntime / Complete Source ZIP、SHA-256、secret scan、clean-room verification、Artifact Attestation、`v1.45.0` Tag / GitHub Releaseを生成します。

GitHub Release公開とProduction Deploymentは別工程です。
