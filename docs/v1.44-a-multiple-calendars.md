# V1.44-A Multiple Calendar / Source

## Scope

V1.44-A adds the internal foundation for multiple Calendars without changing the existing day/week/month view model.

- A Calendar event belongs to one owner-scoped Calendar source.
- Existing events are migrated to an automatically created **既定Calendar**.
- Users can add, rename, recolor and delete additional local Calendars.
- The default Calendar cannot be deleted.
- Deleting a non-default Calendar moves its active events to the default Calendar.
- The Calendar Widget keeps one day/week/month view and adds a source visibility filter.
- Event add/edit forms include a Calendar selector.
- Event copy and drag-and-drop preserve Calendar membership.
- Recurring occurrences inherit the parent series Calendar. An individual occurrence cannot move to another Calendar in this checkpoint.

## Data migration

Apply:

`database/migrations/033_v1_44_calendar_source.sql`

The migration:

1. creates the prefixed `calendar_source` table;
2. adds `calendar_event_source_id` to the existing Calendar event table;
3. creates one default Calendar for owners that already have Calendar events;
4. assigns existing events to that default Calendar.

The application also lazily creates the default Calendar for users who had no Calendar events at migration time.

## UI

The existing Calendar toolbar remains unchanged. A compact source bar is displayed immediately below it.

The source menu supports independent visibility toggles. Visibility is stored locally per Calendar Widget in browser local storage and does not modify event data.

`Calendar管理` opens a separate modal for source creation and maintenance.

## Compatibility

The event source layer is owner scoped and does not change:

- event title/date/time/URL/color/reminder validation;
- recurrence rules;
- occurrence exception storage;
- Task display;
- day/week/month navigation;
- Calendar copy and drag/drop semantics.

If the new migration has not yet been applied, range reads fall back to a virtual default Calendar so existing Calendar rendering is not blocked. Calendar source management requires the migration.

## Not included in V1.44-A

- Google Calendar OAuth / API access
- ICS import/export/subscription
- external Calendar sources
- location / Google Maps
- per-occurrence Calendar reassignment
- shared Calendars or multi-user permissions

## Manual verification

- Existing events appear under 既定Calendar after migration.
- Add a Calendar such as 仕事 and another such as プライベート.
- Add events to different Calendars and confirm both appear in the same month view.
- Toggle each Calendar from the source filter and confirm only that source changes visibility.
- Repeat the visibility check in day and week views.
- Edit an event and move it to another Calendar.
- Copy an event and confirm the copied event initially keeps the same Calendar.
- Drag a non-recurring event and confirm its Calendar remains unchanged.
- Create a recurring event in a non-default Calendar and confirm every occurrence has the same source.
- Edit only one recurring occurrence and confirm Calendar selection is disabled.
- Edit the full recurring series and confirm Calendar selection can be changed.
- Delete a non-default Calendar and confirm its events move to 既定Calendar.
- Confirm 既定Calendar cannot be deleted.
- Confirm the source filter and manager remain usable on a smartphone-width screen.
