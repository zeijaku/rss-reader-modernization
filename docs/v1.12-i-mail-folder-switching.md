# V1.12-I Mail Folder Switching

## Scope

V1.12-I extends the existing read-only Mail Widget with selectable IMAP folders.
The implementation keeps the V1.9/V1.12 Mail safety boundary: the RSS Reader can inspect mail, but it does not mark messages read, move/copy/delete messages, or send mail.

## User-visible changes

- A Folder selector is shown above the Mail search controls.
- Selectable folders are loaded from the authenticated IMAP account.
- `\\Noselect` and `\\NonExistent` entries are not offered as selectable folders.
- The selected folder is remembered for the Mail Widget.
- Unread count, latest messages, subject/from search, sender filter, and refresh operate against the selected folder.
- If a previously saved folder no longer exists, the Widget can reload the current folder list so another folder can be selected.

## Storage / DB compatibility

No new table, column, or migration is required.

Mail Widget configuration now uses schema 2 when saved:

```json
{
  "schema": 2,
  "title": "Mail",
  "item_limit": 5,
  "folder": "INBOX"
}
```

Existing schema 1 configurations remain valid and default to `INBOX`.
Changing the folder updates only the existing `dashboard_widget.widget_config` JSON for that Widget.

## Folder validation flow

1. Connect to the configured Mail Account using the existing pinned/read-only connection path.
2. Obtain the server folder list.
3. Remove non-selectable folder containers.
4. Return the remaining folder paths to the browser.
5. When the user selects a folder, the server obtains the live folder list again.
6. Only a folder still present in that server-provided list can be stored.

The browser is therefore not allowed to choose an arbitrary folder path and have it used without server-side revalidation.

## Read-only behavior

For message lists the selected folder is opened with `EXAMINE`, and the existing direct `MessageQuery` continues to use `leaveUnread()`.

For body preview the selected folder is also opened with `EXAMINE`; the existing plain-text-only / `BODY.PEEK` path is retained.

V1.12-I does not add IMAP STORE, flag updates, move, copy, delete, append, send, or folder-management commands.

## Folder + UID binding

IMAP UIDs are scoped to a mailbox/folder, so V1.12-I does not treat `widget_id + uid` as sufficient for body preview.

The browser sends:

- `widget_id`
- `mail_folder`
- `mail_uid`

The server checks that the submitted folder still matches the folder stored for that owned Mail Widget before using the UID. If the Widget folder changed, the preview request is rejected and the Widget must be refreshed.

## Search / unread interaction

- Folder-wide unread count is obtained for the selected folder.
- Subject/from server search is performed inside the selected folder.
- Sender filter and unread-only controls remain browser-side filters over the returned rows.
- Changing folders clears the sender filter and reloads the Widget.

## Account changes

A newly created Mail Widget starts at `INBOX`.
If an existing Mail Widget is switched to another Mail Account, its folder is reset to `INBOX` before saving so a folder path from the previous account is not silently reused.

## Focused checks

V1.12-I checks are limited to the affected Mail path:

- Mail PHP syntax
- Mail JavaScript syntax
- folder validation
- schema 1 -> schema 2 INBOX compatibility
- selectable-folder filtering
- INBOX resolution
- unknown-folder rejection
- `EXAMINE` retained for list and body paths
- `leaveUnread()` retained
- `BODY.PEEK` path retained
- Folder included with message UID requests
- server-side folder revalidation before persistence
- no new IMAP write operations in the V1.12-I diff
- no DB migration changes
- package exclusion checks

## Not included

- marking messages read/unread
- move/copy/delete
- folder create/rename/delete
- sending/replying
- attachments
- HTML rendering / remote image loading

These remain outside Mail Phase 2.
