# V1.49.1 正式版：更新・確認・復旧手順

## 変更概要
正式版v1.49.0に、ユーザーが動作確認したv1.50.0-dev.16のCalendar予定追加・変更UIの変更だけを反映。Precision Sniperの開発変更やICS連携は含みません。

- Application Version / Asset Revision: `1.49.1`
- Database Migration: **なし**
- 必須Config変更: **なし**
- 保存API・DB操作: **変更なし**
- Runtime ZIP・Complete Source ZIPは既存Release Workflowが作成

## 正式リリースの確認
1. GitHub ActionsのCIがPHP 8.1／8.4とApache隔離テストでGreenであること。
2. Release Workflowのrelease-ready検査、secret scan、両ZIP作成とSHA-256、manifest／CRC、clean-room検証が成功していること。
3. GitHub Releasesの不変タグ`v1.49.1`と公開されたZIPのハッシュを確認すること。
4. CIのPython Playwright等がスキップされた場合は、未実施範囲を別途手動確認すること。

## 適用と動作確認
1. 更新前v1.49.0のコード、vendor、.htaccess、config/local.php、DB、var/とアップロードデータをバックアップ。
2. 正式Runtime ZIPをアプリケーションルートに展開し、app/ と public/ 等のコードを更新。秘密設定や稼働データを消さない。
3. フッターが`RSS Reader Modernization 1.49.1`、キャッシュ更新用`?v=1.49.1`となったことを確認。
4. Calendar追加／変更の見た目、所要時間30分／1時間／2時間・夜間跨ぎ、終日、5色マット四角マーカーと色保存、既存の繰り返し／個別Occurrence／通知／メモ／場所／URL／Calendar選択を確認。
5. モバイルとデスクトップ、ライト／ダークのレイアウトを確認。RSS／Reader Mode／Stock／Task／Mail／Remote Files／Game／2FAの基本操作も確認。

## ロールバック
不具合時は処理を停止し、バックアップ済みのv1.49.0のRuntimeコードとvendorを戻してください。DB Migrationはないためスキーマの巻き戻しは不要です。DBやプライベート設定、ユーザーデータは維持してください。
