# Version 1.12-C - RSS Highlight Keyword UI

Baseline: `rss-reader-modernization-1.12-B-feed-keyword-backend.zip`
Checkpoint version: `1.12.0-dev.3`

## Scope

V1.12-C adds the management UI and safe browser handoff for RSS Highlight keywords.
The actual title highlighting is intentionally deferred to V1.12-D.

Implemented:

- Drawer > カスタマイズ > `RSS Highlight` entry;
- RSS Highlight management modal;
- active keyword list and count;
- keyword add operation using `feed.keyword.create`;
- keyword delete operation using `feed.keyword.delete`;
- max-count UI lock at 50 active keywords;
- initial keyword handoff as non-executable `application/json` data;
- in-browser keyword state kept in sync after create/delete;
- graceful UI disable when the V1.12-B keyword table cannot be read.

Not implemented in this checkpoint:

- highlighted title rendering;
- changes to `renderFeedItems()`;
- Search Feed title decoration;
- per-keyword colors;
- hide rules / Rules Engine;
- Stock Tag linkage;
- Mail Phase 2.

## Database change

No new database change is added by V1.12-C.

The V1.12-B migration remains a prerequisite:

`database/migrations/012_v1_12_feed_keywords.sql`

If that table is unavailable, the Dashboard remains usable and the RSS Highlight modal shows a warning with add/delete controls disabled.

## UI placement

RSS Highlight is a user-wide RSS setting rather than a Stock-only setting, so it is placed in the Drawer under `カスタマイズ`.

The modal contains:

- one Keyword input;
- add button;
- `current / 50` count;
- active Keyword list;
- per-Keyword delete button;
- local status area for create/delete results.

The modal uses the existing Bootstrap 4 / jQuery patterns and does not introduce another UI library.

## Safe browser handoff

The server obtains active keywords with `feed_keyword_list_user()` and emits the result into:

`<script type="application/json" id="rssHighlightKeywordData">...`

The JSON uses:

- `JSON_HEX_TAG`
- `JSON_HEX_AMP`
- `JSON_HEX_APOS`
- `JSON_HEX_QUOT`

This prevents a Keyword containing HTML-looking text or a `</script>` sequence from becoming executable markup.

`dashboard.js` reads the JSON with `JSON.parse()` and validates the ID/value shape before accepting it into the page state.
Keyword list DOM is rebuilt with jQuery `.text()` rather than HTML string insertion.

After add/delete, the in-memory keyword state and the JSON data element are synchronized. V1.12-D can therefore consume `feedKeywordValues()` without adding another database/API read path.

V1.12-C does not alter:
