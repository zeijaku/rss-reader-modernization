# V1.41.1-dev1: Calendar期日強調の再明滅

Application / Asset Revision: `1.41.1-dev.1`。
基準main: `62e2d6ab9fd029c2e1174362e32995a6527cc22d`（V1.41.0正式Release）。

## Scope

- 登録時に「期日を強調する」を有効にした予定だけを対象にする。
- 2日前は従来どおり枠色の強調だけとする。
- 前日から期限までは、表示時に従来どおり1.8秒×3回（約5.4秒）明滅し、その明滅開始から1分の**表示中時間**ごとに短く再明滅する。
- 明滅していない間も赤い上／右／下の強調枠を維持し、左側の予定色ストライプは隠さない。CSSは変更しない。
- 期限を過ぎた予定は従来の期限判定で通常表示へ戻す。
- タブが非表示の間は再明滅タイマーを停止し、復帰時は非表示時間を周期へ加算せず残り時間から再開する。
- `prefers-reduced-motion: reduce` では再明滅クラスを付けず、強調枠だけを維持する。
- occurrence/event識別子ごとに直前の明滅開始時刻を保持し、Calendarカード／予定DOMが差し替わっても同じ周期を引き継ぐ。
- 再明滅はBrowser内の単一timerで行う。1分間隔のAPI通信は追加しない。
- 終日／時間指定、複数日、繰り返し・例外の期限判定、手動更新、表示中3分間隔の差分更新は変更しない。
- DB、API、認証、Tower Defense、Calendar CSSは変更しない。

## Runtime files

V1.41.0からProduction確認用に上書きするRuntime fileは次の2つだけ。

- `app/version.php`
- `public/js/calendar-deadline.js`

DB Migration、config変更、削除fileはない。Asset Revisionが`1.41.1-dev.1`へ変わるため、上書き後は通常の再読込で新しいCalendar JSが取得される。Cacheが残る場合だけHard Reloadする。

## Focused checks

1. ページ下部が`RSS Reader Modernization 1.41.1-dev.1`になっている。
2. PCとSmartphoneで、2日前の強調対象予定が枠だけで明滅しない。
3. 前日〜期限の強調対象予定が表示直後に約5.4秒明滅し、その後は赤い枠を維持する。
4. 初回明滅開始から1分後に同じ予定が再度約5.4秒明滅する。1分ごとのNetwork requestが増えていない。
5. 手動Calendar更新または3分差分更新で表示が差し替わっても、同一予定の明滅周期が不用意にリセットされず、timerが重複しない。
6. タブを非表示にして1分以上置いても裏で明滅周期を消化せず、復帰後は残り時間から再開する。
7. OS/Browserで「視差効果を減らす／Reduce motion」を有効にすると明滅せず、赤い枠だけになる。
8. 期限を過ぎると赤い枠も外れて通常表示へ戻る。
9. 赤／青／緑／黄／紫の予定色ストライプが左側に残る。
10. Calendarの手動更新と表示中3分間隔更新が従来どおりで、TDを含む他Widgetに変化がない。
